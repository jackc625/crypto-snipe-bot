### NEW Integration Gaps Found

**INT-AMOUNT-OUT-NULL (Critical):** Every sell and partial sell records `amountOut: null` in the trades table. `executeFullSell` (exitEngine.ts:480) and `executePartialSell` (exitEngine.ts:576) both pass `amountOut: null` to `insertTrade`. The `sendTxWithRetry` function returns a tx hash, but the ETH received from the swap is never decoded from the transaction receipt. This makes P&L permanently incorrect (sell revenue always zero), the daily loss circuit breaker unreliable, and all dashboard P&L displays wrong.
- **Affected:** DB-03, DB-04, DASH-02, DASH-04, RISK-02
- **Fix:** After `sendTxWithRetry` returns, fetch the tx receipt, decode the Transfer/Swap log to extract ETH output amount, and write it to `amount_out` in the sell row.

**INT-DEDUP-NO-CHAIN (Non-blocking):** `isTokenSniped` query in db.ts:190 uses `SELECT 1 FROM trades WHERE token = ?` with no `AND chain = ?` filter. A token sniped on BSC permanently blocks the same contract address from being sniped on ETH, Base, or Arbitrum. This impairs multi-chain concurrent operation for any token deployed on multiple chains.
- **Affected:** CHAIN-02, CHAIN-03
- **Fix:** Add `AND chain = ?` to the prepared statement and pass chain name at all 3 call sites in bot.ts (lines 204, 381, 560).
- **Status:** CLOSED by Phase 15 — INT-DEDUP-NO-CHAIN retired; isTokenSniped SQL is now chain-scoped (via makeIsTokenSnipedStmt factory), both live call sites bind ctx.chain.name, legacy wrapper call site deleted, pre-Phase-4 chain='mainnet' rows normalized to 'eth' at module load.

**INT-DASHBOARD-API-KEY (Non-blocking):** `DASHBOARD_API_KEY` is not included in `REQUIRED_ENV_VARS` in config.ts. The auth middleware at auth.ts:30 returns HTTP 500 if this env var is unset, but the bot starts with no warning. The entire authenticated dashboard is silently inoperable.
- **Affected:** DASH-01, DASH-02, DASH-03, DASH-04 (usability), FIX-06 (completeness)
- **Fix:** Add `DASHBOARD_API_KEY` to `REQUIRED_ENV_VARS` in config.ts.
