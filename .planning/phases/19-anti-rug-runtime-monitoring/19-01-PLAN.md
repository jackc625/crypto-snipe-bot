<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local SQLite file | bot owns the SQLite file at `data/bot.db`; only the bot process writes it. Boundary is between in-memory app state and persistent disk state. |
| schema migration step | migrateSchema runs at bot startup; a malformed migration risks data loss against prior-version DB files. Boundary is between the v4-shaped on-disk DB and the v5-shaped in-memory expectation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-01-01 | Tampering | `migrateSchema` v4→v5 step | mitigate | Use `CREATE TABLE IF NOT EXISTS` (idempotent), wrap in version-gated `if (version < 5)` block (won't re-run on v5 DBs), do NOT touch existing tables (additive only per ANTIRUG-04). Task 2 test 3 explicitly asserts double-invocation idempotency. |
| T-19-01-02 | Information disclosure | `lp_baseline.pair_or_pool_address` stored COLLATE NOCASE | accept | Address strings are public on-chain data; no PII. Local-only operator UI per UI-SPEC §"Cross-Cutting Constraints" item 1. |
| T-19-01-03 | Denial of service | `lp_baseline` table grows unbounded | accept | One row per open trade; trades close → operator periodically wipes via existing DB maintenance. Phase 19 closes the lifecycle by deleting the row when `amount_remaining=0` (Plan 19-05 D-TERMINATION). Row count bounded by concurrent open positions (~10s max). |
| T-19-01-04 | Repudiation | Schema-migration log line | mitigate | `logger.info('Created lp_baseline + chain_state tables (schema version 5)')` provides audit trail of when v5 was applied. Matches Phase 7 v3 migration log discipline. |

**Residual risk:** None at `high`. SQLite migrations are well-trodden territory in this codebase (Phases 3, 7, 14 each shipped additive migrations without regression). The single material risk would be a TYPO in the CREATE TABLE statement that makes the prepared statement fail at runtime against the wrong column name — caught by Task 2's tests at unit-level before any plan beyond 19-01 lands.
