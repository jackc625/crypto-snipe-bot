(2) **Module-level child logger:** `const log = logger.child({ module: 'antiRug:detector' });`

(3) **Position registry (per-chain, in-memory):**
- `interface RegisteredPosition { tradeId: number; chain: string; tokenAddress: string; pairOrPoolAddress: string; dex: DexConfig; feeTier: number | null; baseline: LpBaselineRow; }`
- `const positionRegistry = new Map<string, Map<string, RegisteredPosition[]>>();` — outer key chain, inner key lowercased pairOrPoolAddress, value is an array (handles multiple positions on the same pair).
- Per-chain Map ensures cross-chain isolation; per-pair array handles the rare same-pair-multiple-positions case.

(4) **Per-chain WS state:**
- `interface ChainAntiRugState { wsProvider: WebSocketProvider | null; heartbeatInterval: NodeJS.Timeout | null; reconnectAttempts: number; lastSeenBlock: number; healthState: 'connected' | 'reconnecting' | 'disconnected'; lastPongTs: number; }`
- `const chainState = new Map<string, ChainAntiRugState>();` — keyed by chain.name.

(5) **Public API exports:**

- `export function registerAntiRugPosition(ctx, dex, tokenAddress, pairOrPoolAddress, tradeId, feeTier)`:
  - Loads `baseline = loadLpBaseline(tradeId)` (Plan 19-03 helper); if null, log error and skip (Plan 19-05 should have called snapshotLpBaseline first).
  - Insert into positionRegistry under chain+lowercased(pairOrPoolAddress) key.
  - If this is the first position on this chain, also kick off `startChainAntiRugListener(ctx)` if not already started.
  - Update the WS subscription's address filter to include the new address (if WS already running, restart the subscription with the union of addresses).

- `export function unregisterAntiRugPosition(chain: string, tradeId: number)`:
  - Remove from positionRegistry by searching for tradeId across the per-chain Map.
  - If chain has zero positions remaining, optionally stop the WS listener (discretionary; recommendation: keep listener running, update address filter to empty — saves reconnect cost on the next buy).

- `export async function startChainAntiRugListener(ctx: ChainContext): Promise<void>`:
  - If `ctx.wsProvider == null`, dispatch to HTTP polling fallback (per 19-PATTERNS.md §"detector.ts" lines 170-197).
  - Compute topic filter union: V2 topics (PAIR_BURN_TOPIC, PAIR_TRANSFER_TOPIC) + V3 topics (POOL_BURN_TOPIC, POOL_COLLECT_TOPIC).
  - Compute address filter: union of all registered pair/pool addresses for this chain.
  - `wsProvider.on(filter, (logEvent) => dispatchEvent(ctx, logEvent))`.
  - Set up heartbeat per 19-PATTERNS.md §"detector.ts" lines 144-167 (Test 21 covers).
  - Register 'close' handler for reconnect: copies the existing src/bot.ts:660-752 pattern (exponential backoff 1s → 60s); on reconnect, re-subscribe with same filter AND call `await backfillSinceLastSeen(ctx)` (Test 22 + 23).
  - On connect success, `broadcast('chain_ws_health_change', {chain, state: 'connected', lastPongTs: Date.now()})`.

- `export async function evaluateRugSignals(ctx: ChainContext, position: RegisteredPosition, logEvent: Log): Promise<RugEvaluation>`:
  - Parse the event log's topic to determine V2 Burn vs V2 Transfer vs V3 Burn vs V3 Collect.
  - **Signal 1 — LP-removed-pct:**
    - V2: read `pair.getReserves()` (post-event reserves) + `pair.totalSupply()`; compute pct removed vs `position.baseline.v2_lp_total_supply`.
    - V3: read `pool.liquidity()` (current active liquidity); compute pct removed vs `position.baseline.v3_active_liquidity`.
    - Trips if `pct > ctx.chain.antiRug.lpRemovalPct`.
  - **Signal 2 — destination NOT in allowlist:**
    - V2 Burn: destination = decoded `to` field.
    - V2 Transfer: destination = decoded `to` field (per ANTIRUG-03 — burn to dead).
    - V3 Burn: destination = decoded `owner` field per RESEARCH CRITICAL #3.
    - V3 Collect: destination = decoded `recipient` field (NOT indexed in V3 Collect — must decode from data).
    - Use `isAddressAllowlisted(ctx.chain.antiRug.allowlistV2 if V2 else allowlistV3, destination)`.
    - If `hit=true`, set `allowlistHit='safe'` and lockerName; if `hit=false`, set `allowlistHit='unsafe'` and signal-2 trips.
  - **Signal 3 — reserves/sell-sim below threshold:**
    - V2: compute `v2ReservePctBelow = (1 - currentReserves / baselineReserves) * 100`; trips if `currentReserves / baselineReserves < 0.5`.
    - V3: read DexConfig for `quoterAddress` (from `ctx.chain.dexes.find(d => d.dexType === 'v3').quoterAddress`); call `quoter.quoteExactInputSingle.staticCall({tokenIn: position.tokenAddress, tokenOut: ctx.chain.wethAddress, amountIn: BigInt(position.baseline.amountInWei OR a probe amount), fee: position.feeTier, sqrtPriceLimitX96: 0n})`; compare result `[0]` against baseline expected. If revert, signal-3 trips per fail-closed.
  - **Evaluation:**
    - If allowlistHit='safe' (signal 2 did NOT trip because destination IS in allowlist), return `{verdict: 'allowlisted', signals, lockerName}` + log `op: 'antirug.allowlist-hit'` per D-LIST-AUDIT.
    - If all three signals tripped, return `{verdict: 'unsafe', reason: 'three-signal-trigger', signals}`.
    - Otherwise return `{verdict: 'safe', reason: 'partial-signal', signals}`.
    - On any thrown error during signal evaluation, return `{verdict: 'unknown', reason: error.message}` — DO NOT return 'safe' on RPC failure (vacuous-pass anti-pattern).

(6) **Confirm-after-N-blocks gate** — internal helper invoked by dispatchEvent:
- On `evaluateRugSignals` returning verdict='unsafe', schedule a re-evaluation after `ctx.chain.antiRug.confirmBlocks` blocks via a block-number-watching loop (or simple `setTimeout(N * blockTimeMs)` — discretionary; recommendation: actual block-number watch via `ctx.httpProvider.on('block', handler)` is more accurate than time-based).
- On re-eval, if verdict is STILL 'unsafe' (all three signals still trip), dispatch to `triggerAntiRugExit(ctx, dex, token, feeTier, tradeId, evaluation)` (imported from Plan 19-05's `src/anti-rug/exitTrigger.ts`). Since Plan 19-05 is a downstream dependency, this plan stubs the import with `// TODO Plan 19-05 export` and the integration test mocks the trigger.
- If verdict de-tripped (any signal cleared), log `op: 'antirug.signal-detripped', tradeId, originalSignals, currentSignals` and abort.
- If `confirmBlocks === 0`, dispatch synchronously without scheduling.

(7) **Heartbeat + reconnect** per 19-PATTERNS.md §"detector.ts" lines 113-167:
- After WS open: `(rawWs as any).isAlive = true; rawWs.on('pong', heartbeat);`
- 30-second `setInterval` checks `isAlive`; if false, `rawWs.terminate()` (triggers close → reconnect); if true, set false and `rawWs.ping()`.
- On 'close' handler: clearInterval, exponential backoff reconnect (1s → 60s), on reconnect re-subscribe + call backfill.

(8) **Backfill on reconnect** per 19-PATTERNS.md + 19-RESEARCH.md §5/§6:
- `async function backfillSinceLastSeen(ctx, wsProvider)`:
  - Read `lastSeen = getChainState.get(ctx.chain.name)?.last_seen_block ?? currentBlock`.
  - `currentBlock = await ctx.httpProvider.getBlockNumber()`.
  - `gapBlocks = currentBlock - lastSeen`.
  - If `gapBlocks > ctx.chain.antiRug.maxBackfillBlocks`: pino error + `sendCtxAlert(ctx, '[GAP DETECTED] {chain} missed {N} blocks ({lastSeen}-{currentBlock})')` + `broadcast('antirug_event', {chain, kind: 'gap-detected', gapBlocks, fromBlock: lastSeen, toBlock: currentBlock, timestamp: Date.now()})` + RETURN without processing.
  - Else: chunked iteration. For each chunk of `backfillCapBlocks` from `lastSeen+1` to `currentBlock`:
    - `events = await ctx.httpProvider.getLogs({address: <union>, fromBlock: chunkStart, toBlock: chunkEnd, topics: [<union>]})`.
    - For each event: `evaluation = await evaluateRugSignals(ctx, position, event)`; on verdict='unsafe', log `op: 'antirug.backfill.too-late', evaluation` and broadcast `antirug_event` with `outcome: 'too-late'` — NEVER call triggerAntiRugExit on backfilled events per D-BACKFILL anti-pattern.
  - After processing, `upsertChainState.run(ctx.chain.name, currentBlock, Math.floor(Date.now()/1000))`.

- After each poll, `upsertChainState.run(ctx.chain.name, currentBlock, ts)`.
- Used when `ctx.wsProvider == null`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| WebSocket event stream from RPC | external (RPC-controlled) input crosses into the detector; malformed events, replay attacks, or hostile sequences could trigger spurious exits or silent monitoring failure |
| `getLogs` backfill response | external input on reconnect; a malicious/buggy RPC could return forged historical events leading to logged-but-not-executed would-have-sold telemetry distortion |
| heartbeat ping/pong | external timing-channel; absence of pong is the failure signal; a stuck-but-alive WS would silently miss events without heartbeat |
| QuoterV2.staticCall response | external view-call result feeds signal-3; a manipulated quote (e.g., MEV-attacked pool state at the read block) could trip false-positive signal-3 |
| confirm-after-N-blocks gate | bot-internal timing dependency on block subscription; missed blocks (e.g., RPC drop during the gate window) could trap the dispatch indefinitely |
