## Component Changes (Phase-Specific)

This phase modifies existing components rather than creating new ones. The following specifies the exact visual changes.

### 1. TradeTable.tsx -- Add sell_count indicator

**What changes:** The Status column displays partial sell count when `sellCount > 1`.

| State | Current Display | New Display |
|-------|----------------|-------------|
| Open, no sells | Green badge: "open" | Green badge: "open" (unchanged) |
| Open, with partial sells | Green badge: "open" (incorrect) | Green badge: "open" + muted text: "(2 sells)" |
| Closed, single sell | Gray badge: "closed" | Gray badge: "closed" (unchanged) |
| Closed, multiple sells | Gray badge: "closed" (no indication) | Gray badge: "closed" + muted text: "(3 sells)" |

**Sell count display spec:**
- Position: Inline after the status badge, separated by 4px gap (gap-1)
- Font: 12px (text-xs), weight 400, color --color-text-muted
- Format: `({N} sells)` where N is sell_count. Omit entirely when sell_count <= 1.
- Container: Wrap badge and count in a `flex items-center gap-1` div

**Open/closed detection change:**
- Current: `hasExitRevenue = trade.sellTime !== null` -- BROKEN when partial sells set sell_time on open positions
- New: Use `trade.action` field which now carries `'closed'` or `'open'` from the API (derived from `buy_status` in the query). Do not use sell_time for open/closed determination.

### 2. Trade type (api.ts) -- Add sellCount field

```typescript
export interface Trade {
  // ... existing fields unchanged ...
  sellCount: number;          // New: count of sell + partial_sell events
  action: 'open' | 'closed'; // Changed: now derived from buy_status, not buy/sell action
}
```

**Backward compatibility:** `sellCount` defaults to 0 when API returns no value (use `trade.sellCount ?? 0` in components).

### 3. PnLChart.tsx -- No visual changes

The chart component itself does not change. The data it receives will now include partial_sell events as additional data points. The existing dual-area-series rendering (positive green / negative red) handles this automatically since it processes `{ time, value }` pairs regardless of source.

**Data change only:** The `/api/risk/pnl` endpoint will return more data points (each partial_sell adds a cumulative P&L step). The chart renders them identically to full sell data points.

### 4. PositionTable.tsx -- Partial P&L visibility

**What changes:** The P&L column for open positions with partial sells now shows the partial realized P&L instead of unrealized-only P&L.

| State | Current Display | New Display |
|-------|----------------|-------------|
| Open, no sells, no P&L | "-.---" | "-.---" (unchanged) |
| Open, partial sells taken | "-.---" or unrealized only | "+0.0234" (partial realized P&L, green) |

**No component code change needed** -- the PositionTable already renders `formatPnL(pos.pnl)` with `pnlColor(pos.pnl)`. The data layer fix makes `pos.pnl` include partial sell revenue for open positions (D-03). The visual output changes automatically.

**Expanded row "Partial Sells" field:**
- Current: Shows `{N} tiers completed` from exitState
- New: No change needed -- this reflects exit strategy tiers, not financial data

### 5. ExposureDonut.tsx -- No visual changes

The donut chart renders whatever exposure values the API returns. After D-04 fixes, exposure values will be lower (subtracting partial sell returns). No component code or visual change needed.

### 6. RiskGauge.tsx -- No visual changes

Risk gauges render from API data. Daily loss values will be more accurate after D-05 fix. No component code change needed.

## Interaction Contract

### Data Flow Changes (invisible to user, affects what they see)

| Data Source | Before | After | User-Visible Effect |
|-------------|--------|-------|---------------------|
| getPnL() | Ignores partial_sell rows | Aggregates partial_sell + sell per buy | P&L values include partial sell revenue |
| getTotalExposure | SUM(amount_in) for pending | SUM(amount_in - partial_sell_returns) | Exposure values decrease after partial sells |
| getDailyRealizedLoss | sell events only | sell + partial_sell events | Daily loss circuit breaker more accurate |
| P&L chart data | sell events only | sell + partial_sell events | More data points on cumulative P&L curve |

### No New Interactions

This phase does not add any new user interactions. All existing click handlers, sort controls, filter controls, pagination, and expand/collapse behaviors remain unchanged.
