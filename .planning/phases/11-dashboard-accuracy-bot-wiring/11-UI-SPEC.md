## Data Shape Changes (Phase 11 Specific)

This section replaces the standard component inventory since Phase 11 adds no new components. It specifies how existing components consume changed data.

### Position Type Extension

The `Position` interface in `dashboard/src/types/api.ts` gains two fields:

| Field | Type | Source | Visual Treatment |
|-------|------|--------|-----------------|
| `priceStale` | `boolean` | D-03 fallback flag | When `true`, show warning indicator next to currentPrice |
| `unrealizedPnl` | `number \| null` | D-05 live computation | Replaces `pnl` (realized_pnl) for open positions display |

### PositionTable Changes

**Current price cell** (`<td>` in PositionRow):
- When `priceStale === false`: render `currentPrice` in `font-mono text-sm text-right` (unchanged)
- When `priceStale === true`: render `currentPrice` in `font-mono text-sm text-right text-warning` with a `(stale)` suffix in `text-xs text-text-muted` inline after the value
- Tooltip text when stale: "Live price unavailable. Showing last known value."

**P&L cell**:
- Use `unrealizedPnl` instead of `pnl` for the display value
- Color logic unchanged: positive = `text-profit`, negative = `text-loss`, null = `text-text`
- Format unchanged: `formatPnL()` with +/- prefix and 4 decimal places

### Health Response Extension

The `HealthResponse` interface gains:

| Field | Type | Visual Treatment |
|-------|------|-----------------|
| `telegramConnected` | `boolean` | StatusDot in sidebar footer, below WebSocket status |
| `telegramError` | `string \| null` | Tooltip text on StatusDot when disconnected |

### Sidebar Footer Addition

Below the existing WebSocket status line in `Sidebar.tsx`, add a Telegram status line:

```
[StatusDot] Telegram: Connected
[StatusDot] Telegram: Disconnected
```

- Use existing `StatusDot` component with `status: 'connected' | 'disconnected'`
- Label text: `text-xs text-text-muted` (12px, #94a3b8)
- Only visible when sidebar is expanded (hidden when collapsed, same pattern as WS status)
- Spacing: `mt-1` (4px) between WS status line and Telegram status line

### Chain Restart Response

The chain start endpoint response may include a `warnings` array. Visual treatment:

- When `warnings.length > 0` after a successful restart: show a warning banner inside the chain card
- Banner style: `border-l-2 border-warning bg-surface rounded-r-lg px-4 py-3` (matches existing force sell error banner pattern)
- Banner text: `text-sm text-warning` with each warning on its own line
- Banner is dismissible (X button, `text-text-muted hover:text-text`)
- If no warnings: no banner, chain card shows normal "running" state

## Interaction States

### Position Price Loading

Between page load and first `queryPrice` response:
- `currentPrice` shows `"-.----"` (existing null format from `formatEth`)
- `priceStale` is `false` until a fallback occurs
- No spinner -- the 5s WebSocket push will populate data quickly

### Stale Price Indicator

When `priceStale === true` on a position row:
- Current price text color changes from default (`text-text`) to `text-warning` (#eab308)
- Append `(stale)` in `text-xs text-text-muted` after the price value
- The `title` attribute on the price cell provides the tooltip explanation
- No animation, no icon -- keep the table scannable

### Telegram Status States

| State | StatusDot | Label | When |
|-------|-----------|-------|------|
| Connected | `connected` (green, pulsing) | "Telegram: Connected" | Client connected and listening |
| Disconnected | `disconnected` (red, static) | "Telegram: Disconnected" | Client failed or lost connection |
| Not configured | `stopped` (yellow, static) | "Telegram: Not configured" | Env vars missing, listener skipped (D-14) |

### Chain Restart Flow

1. User clicks "Start" button on stopped chain card (existing UI)
2. Existing confirmation dialog appears (unchanged)
3. On confirm, POST request fires (existing behavior)
4. **NEW:** Response may include `warnings: string[]`
5. If `warnings.length === 0`: chain card transitions to "running" state (existing behavior)
6. If `warnings.length > 0`: chain card transitions to "running" state AND a warning banner appears below the chain status showing each warning
