<objective>
Fix fork test nonce caching bug that causes 6 of 7 tests to fail.

Purpose: UAT Gap 3 identified that ethers v6 JsonRpcProvider caches RPC responses including
eth_getTransactionCount. On a Hardhat mainnet fork, the default account has a high nonce (~6158)
from real mainnet transactions. The cached stale nonce causes "nonce too low" errors starting at
test 2, cascading into all subsequent tests. This is a pre-existing bug from Phase 09 (the fork
test was written but never executed against an actual fork). The fix is a single constructor
option change.

Output: Fixed fork test that passes all 7 lifecycle steps.
</objective>

In the `beforeAll` block of `test/fork/snipeLifecycle.test.ts`, change line 42 from:

```typescript
provider = new ethers.JsonRpcProvider('http://127.0.0.1:8545');
```

to:

```typescript
provider = new ethers.JsonRpcProvider('http://127.0.0.1:8545', undefined, { cacheTimeout: -1 });
```

The `cacheTimeout: -1` option disables ethers v6's default RPC response caching. Without this,
the provider caches `eth_getTransactionCount` responses, causing stale nonce values when sending
rapid sequential transactions to the Hardhat fork node. This is a known ethers v6 issue
(https://github.com/ethers-io/ethers.js/issues/4549).

No other changes needed. The test logic is correct -- only the provider caching behavior causes
failures.
