Fix the Flashbots MEV strategy to return the real transaction hash (instead of a synthetic identifier) so receipt decoding works for ETH mainnet Flashbots sells. **Stronger verification posture (per REVIEWS.md — Codex HIGH severity):** Grep can prove text presence but not behavior. For a P&L-critical, money-accounting fix, this plan now adds mocked-module tests that prove `insertTrade.run` receives non-null `amountOut`, `gasCost`, and `block` when `decodeReceipt` returns data, AND that nulls are recorded when `sendTxWithRetry` returns `void` (legacy path). Grep checks are retained as cheap sanity, but the real verification is the test run.

Purpose: This is the integration plan that closes the INT-AMOUNT-OUT-NULL gap. After this plan, all sell and partial_sell rows will have non-null `amountOut` when the sell receipt contains a recognized wrapped-native payout event, which flows through the existing `getPnL` query to produce correct realized P&L. No database schema changes or query modifications needed — the existing `COALESCE` pattern handles the transition from null to real values.

Output: Modified `src/exitEngine.ts`, `src/utils/mevStrategies/flashbots.ts`, new execution-path test file, and updated MEV strategies integration test. All existing tests still pass.

Note on legacy txManager path: The legacy single-chain overload at `src/utils/txManager.ts:132` and `:144` still returns `void` (unchanged in this phase). The new `if (txHash)` guard in exitEngine handles this gracefully — sells via the legacy path will continue to record nulls. This is intentional and out of scope for Phase 14; the multi-chain path (used by exitEngine) always returns a real hash string via `strategy.sendTransaction`.

In `src/utils/mevStrategies/flashbots.ts`, replace line 76:

```typescript
return `flashbots_bundle_block_${targetBlock}`;
```

With the guarded extraction:

```typescript
const realHash = bundle.bundleTransactions?.[0]?.hash;
if (!realHash) {
    throw new Error(`Flashbots bundle response missing bundleTransactions[0].hash for block ${targetBlock}`);
}
return realHash;
```

This throws loudly if the Flashbots library ever returns a response shape missing the hash field, rather than silently returning `undefined` (which would then be cast to `string` and break receipt decoding downstream). This is an implementation-only change — the `MevStrategy.sendTransaction` interface still returns `Promise<string>`, consistent with D-04.

The `bundle` variable is typed as `FlashbotsTransactionResponse` which has `bundleTransactions: Array<TransactionAccountNonce>` where `TransactionAccountNonce.hash` is a string containing the real transaction hash.
