## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| bot → mainnet RPC (signing) | Every signed tx crosses here; concurrent submits for one wallet contend for a nonce | signed txs, nonces |
| bot → mainnet RPC (read/submit) | A hung RPC call parks the single Node event loop, blocking all monitoring | provider reads, submits |
| in-memory monitoring ↔ persisted exit_state (SQLite) | A process restart loses in-memory monitoring; persisted state is the only recovery source | exit_state rows, anti-rug registry |
| wallet balance ↔ submitted priority fee / buy decision | An over-bid sell or an unaffordable entry strands capital (thin-wallet trap) | balances, fees |
| per-position poll loop ↔ sell submission | A blocking sell on the poll critical path starves ALL positions' monitoring | poll ticks, sell submits |
| private Flashbots relay ↔ public mempool | The fallback transition can double-sell if the private bundle lands late; the public sell is sandwich-exposed | bundle/tx hashes, balances |
| exit-attempt result ↔ position-monitoring lifecycle | A submit-report that lies (false negative) can strip rug protection from a real held position | exit outcomes, anti-rug subs |
| operator ↔ a wedged process holding funds | A frozen bot ignores Ctrl+C while holding an open position | OS signals |
| fork-proven wiring ↔ real-capital mainnet behavior | A fork has no Flashbots relay; passing fork tests do not prove the real private→public transition | test evidence vs live artifacts |
| persisted exit_failed_held state ↔ post-restart monitoring | A reboot reconstructs monitors/anti-rug from the DB; a row the scans miss is unprotected | exit_failed_held rows |

## Accepted Risks Log

| Risk ID | Threat Ref | Rationale | Accepted By | Date |
|---------|------------|-----------|-------------|------|
| RISK-21.2-SANDWICH | T-21.2-SANDWICH | The GUARANTEED exit path is a public-mempool sell (`swapExactTokensForETHSupportingFeeOnTransferTokens`), which is inherently sandwich-exposed. Per D-EXIT-INCLUSION this is an accepted tradeoff: a sandwiched sell that LANDS beats a stranded position that cannot exit at all (the Finding A thin-wallet trap / LADYS harm). The worst case is bounded by reason-aware slippage — routine fallbacks reuse the configured exit slippage (~5%), anti-rug widens (15%, 10% floor) to maximize landing while liquidity drains (`src/exitEngine.ts:464-472`), and `computePublicMinOut` applies a 99% effective-slippage upper clamp so `minOut` can never collapse to 0 even on a misconfigured knob (`src/exitEngine.ts:483-491`). A double-sell (the unrecoverable harm) is separately prevented by T-21.2-DOUBLESELL. | Plan author (D-EXIT-INCLUSION, register authored at plan time); audit-confirmed mitigation present | 2026-05-29 |
