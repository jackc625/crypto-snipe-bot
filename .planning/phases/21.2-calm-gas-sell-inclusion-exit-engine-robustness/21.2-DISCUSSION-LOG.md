## Calm-gas exit inclusion (Finding A)

### Q1 — Primary inclusion mechanism
| Option | Description | Selected |
|--------|-------------|----------|
| Escalate private, then public fallback | Higher independent sell ceiling (± coinbase bribe) first; public-mempool fallback after N non-inclusions (promote recover-sell-ladys.ts) | ✓ |
| Public-mempool fallback only | Skip private escalation; go public on non-inclusion | |
| Private only, bid higher / bribe | Never expose to public mempool; raise ceiling / bribe | |

**User's choice:** Escalate private, then public fallback.
**Notes:** For an exit, guaranteed inclusion beats MEV-perfection — a stranded position (esp. anti-rug) is the worse outcome. Layered = protection when it works, exit when it doesn't.

### Q2 — Fallback trigger
| Option | Description | Selected |
|--------|-------------|----------|
| Reason-aware (urgency-driven) | Anti-rug → public fast (0-1 private attempts); routine exits escalate private N then fall back | ✓ |
| Fixed N non-inclusions | Same trigger for all exits | |
| Time-budget (whichever first) | Fall back on N OR a wall-clock deadline | |

**User's choice:** Reason-aware (urgency-driven).
**Notes:** A rug can drain liquidity in a single block — anti-rug must not retry private bundles while it proceeds.

### Q3 — Exit-affordability entry gate
| Option | Description | Selected |
|--------|-------------|----------|
| Hard entry gate | Refuse the snipe unless the wallet can afford the worst-case guaranteed (public) exit + buffer | ✓ |
| Public fallback is enough | No new gate; existing reserve covers a normal-gas public sell | |
| Operator warning only | Preflight/log warning, no hard block | |

**User's choice:** Hard entry gate.
**Notes:** Never enter a position you cannot exit — make the thin-wallet trap impossible, not just survivable. Strengthen reconciliation.ts affordability reserve to target the guaranteed exit.

### Q4 — Public-fallback double-sell guard
| Option | Description | Selected |
|--------|-------------|----------|
| Full reconcile + balance recheck | Re-run inclusion reconciliation on last private attempt (abort if landed) + re-fetch balance (sell only held) | ✓ |
| Nonce check only | Reuse the nonce-advanced guard alone | |
| Balance recheck only | Re-read balance before public sell | |

**User's choice:** Full reconcile + balance recheck.
**Notes:** Reuses 21.1 D-RECONCILE-RECEIPT + D-NONCE-SAFE-RETRY; prevents both double-sell and selling-nothing.

## Failed-exit protection (Finding D)

Due-diligence finding surfaced during discussion: Phase 19's `D-TERMINATION` always
meant "unregister when the position *closes*"; the bug wired the failed-exit error
path (`exitEngine.ts:561-573`) to the same teardown. Fixing Finding D is correcting
a misapplication, NOT reversing D-TERMINATION.

### Q1 — Monitoring teardown condition
| Option | Description | Selected |
|--------|-------------|----------|
| Keep anti-rug forever; bound exit retry | Anti-rug until genuine close; routine retries bounded (N) then pause+hard-alert; emergency anti-rug exits still fire | ✓ |
| Never tear down on failure | Monitor while held; retry indefinitely | |
| Operator-gated after first failure | Keep anti-rug + alert; pause auto-retry until operator approves | |

**User's choice:** Keep anti-rug forever; bound exit retry.
**Notes:** Protects against rug absolutely while bounding gas-burn on a stuck/sell-reverting position.

### Q2 — Held-vs-closed determination
| Option | Description | Selected |
|--------|-------------|----------|
| On-chain balanceOf is truth | balanceOf is source of truth; ~0=closed, >dust=held | ✓ |
| Trust reconciled sell result | Use Area-1 reconciliation outcome | |
| DB amount_remaining | Use DB status | |

**User's choice:** On-chain balanceOf is truth.
**Notes:** D-OP-DB-TRUTH applied to the exit lifecycle; LADYS proved the submit report can be a false-negative while the chain balance is correct.

### Q3 — Persisted state / restart-resilience
| Option | Description | Selected |
|--------|-------------|----------|
| Persist live + distinct status | Don't delete exit_state; distinct 'exit_failed_held' status + failure counter; restart resumes | ✓ |
| Persist live, reuse 'open' | Same but no new status; failures in exit_state only | |
| Persist live + startup reconciliation sweep | Option 1 + boot-time balance reconciliation of all positions | (deferred) |

**User's choice:** Persist live + distinct status.
**Notes:** In-scope fix with operator-visible status; the broader startup-sweep deferred (see below).

## Poll-loop starvation (Finding C)

Load-bearing constraint surfaced: the bot uses a single wallet, so concurrent sells
contend for the nonce; anti-rug can itself trigger a sell, so the exit poll isn't
the only submitter.

### Q1 — Decoupling model
| Option | Description | Selected |
|--------|-------------|----------|
| Serialized worker + non-blocking poll | Ticks enqueue+return; single serial exit worker; per-position lock | ✓ |
| Async-per-exit + per-position lock | Background task per exit; still needs a nonce mutex | |
| Keep in tick, fix the blocking | Yield + re-entrancy guard, no restructure | |

**User's choice:** Serialized worker + non-blocking poll.
**Notes:** Serial submission is nonce-safe by construction; poll cadence never blocks; per-position lock prevents re-entrant self-sell.

### Q2 — Nonce-authority scope
| Option | Description | Selected |
|--------|-------------|----------|
| All wallet submits | Buys, exit sells, anti-rug sells, public fallback, approvals through one nonce authority | ✓ |
| Exit family only | Exit + anti-rug sells + fallback; buys as-is | |
| Exit worker only | Only the new worker is serial | |

**User's choice:** All wallet submits.
**Notes:** Eliminates the nonce-collision (double-spend) class bot-wide; natural conclusion of 21.1's D-SHARED-HELPER.

### Q3 — Queue ordering
| Option | Description | Selected |
|--------|-------------|----------|
| Priority by urgency | anti-rug > urgency/stop-loss > trailing > partial | ✓ |
| FIFO (trigger order) | Strict trigger order | |
| You decide / planner | Leave to planner | |

**User's choice:** Priority by urgency.
**Notes:** In a rug/crash cascade the most capital-protecting exits go first.

## Freeze / kill-safety (Finding B)

Root cause is explicitly a research/debug task; these decisions are the
defense-in-depth guarantees that hold regardless of root cause.

### Q1 — Defense-in-depth posture
| Option | Description | Selected |
|--------|-------------|----------|
| Watchdog + hard SIGINT + RPC timeouts | All three layers | ✓ |
| Hard SIGINT + RPC timeouts | Two layers, no watchdog | |
| Fix root cause only | Targeted timeouts only | |

**User's choice:** Watchdog + hard SIGINT + RPC timeouts.
**Notes:** A funded live bot must be always killable and never silently wedged.

### Q2 — SIGINT kill behavior
| Option | Description | Selected |
|--------|-------------|----------|
| Two-stage, time-bounded | First SIGINT graceful (bounded grace); second SIGINT or timeout → force exit | ✓ |
| Immediate force-exit | process.exit() right away | |
| Graceful with single hard timeout | One timeout, no second-Ctrl+C shortcut | |

**User's choice:** Two-stage, time-bounded.
**Notes:** Abandoning an in-flight submit is safe via restart-resume (D-PERSIST-FAILED-HELD) + the nonce authority.

### Q3 — Watchdog action on budget overrun
| Option | Description | Selected |
|--------|-------------|----------|
| Abort the op, keep bot alive | Abort stuck op + alert; bot keeps monitoring; stuck position stays held+monitored | ✓ |
| Force-restart the process | Force-exit; rely on supervisor + restart-resume | |
| Alert only | Detect + alert, no abort | |

**User's choice:** Abort the op, keep bot alive.
**Notes:** Surgical — one wedged submit never takes down monitoring of other positions.
