# Phase 21.2 Plan 12: CR-01 Worker-Exit Deadlock + CR-02 No-Double-Sell Phantom-Hash Fixes Summary

**Single-level per-wallet locking kills the re-entrant withNonceLock deadlock on every worker-driven exit (sell-lock no longer strandable), and the no-double-sell guard now reconciles the strategy's actually-broadcast tx (via a BroadcastHandle side-channel) + fails safe on an inconclusive private inclusion — both proven by REAL-path regression tests that fail against the pre-fix code.**

## Accomplishments

- **CR-01 (deadlock) fixed:** the `ExitWorker.drain` no longer wraps the executor in an OUTER `withNonceLock`. `executeFullSell` already routes every signing site (private-leg approval, public-fallback approval + swap, partial submit) through `withNonceLock(ctx.wallet.address, …)` internally, and the drain is serial-by-construction — so the per-wallet authority holds without a double-lock. The watchdog stays at the worker level (wall-clock bound) but OUTSIDE any nonce lock. A real worker→`executeFullSell`→approval exit now RESOLVES (no hang), reaches `finally{releaseSellLock}`, and a subsequent direct anti-rug exit can acquire the sell-lock (no longer stranded).
- **CR-02 (double-sell) fixed:** the throwaway local pre-sign in `escalatePrivateSell` is DELETED. `lastSignedHash`/`lastNonce` are now the ACTUALLY-broadcast tx surfaced through an optional `BroadcastHandle` out-param the strategy populates after every submit (threaded `submitWithReconciliation` → `MevStrategy.sendTransaction` → `sendTxWithRetry` → `escalatePrivateSell`). Guard 2a's `reconcileInclusion` therefore probes a hash that really hit the chain and can detect a late land before the fallback. Added the interim fail-safe: an inconclusive (`landed-not-ours`) reconcile DEFERS the public fallback (keep held + monitored) rather than selling on the optimistic balanceOf snapshot.
- **Cardinal-lesson antidote:** both new tests exercise the REAL path (real `withNonceLock`, real `executeFullSell` wiring through the worker, real broadcast-vs-probed hash equality) and each demonstrably FAILS against the pre-fix code — re-verified by checking out the pre-fix `src` (commit 5de83dc) and running both tests (5 failures: 2 deadlock, 3 phantom-hash/double-sell), then restoring the fix (5 passing).

## EXACT src changes (load-bearing)

**CR-01 — worker locking change** (`src/exitEngine.ts`, `ExitWorker.drain`):
```ts
// BEFORE (deadlocks):
await withNonceLock(item.ctx.wallet.address, () =>
    this.watchdog(item, () => this.executor(item)),
);
// AFTER (single-level locking):
await this.watchdog(item, () => this.executor(item));
```

**CR-02 — broadcast-hash threading** (`src/utils/txManager.ts`, `escalatePrivateSell`): the entire pre-sign block (`getTransactionCount` → `populateTransaction` → `signTransaction` → `keccak256`) is deleted; replaced by a `const broadcast: BroadcastHandle = {}` passed as `sendTxWithRetry(txBuilder, ctx, attempts, undefined, undefined, gasMultiplier, broadcast)`, with the not-landed return becoming `{ landed: false, lastSignedHash: broadcast.signedTxHash, lastNonce: broadcast.submittedNonce }`. `submitWithReconciliation` writes `broadcast.signedTxHash = result.signedTxHash; broadcast.submittedNonce = result.submittedNonce;` after each submit.

**CR-02 — guard 2a fail-safe** (`src/exitEngine.ts`): added an `else if (recon.outcome === 'landed-not-ours')` branch that sets `privateInclusionInconclusive = true` (+ alert), then `if (privateInclusionInconclusive) return false;` BEFORE the balanceOf branch (2b) — the public fallback never runs on an unprovable private inclusion.
