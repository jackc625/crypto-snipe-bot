# Phase 21.3: Buy-Leg Calm-Gas Flashbots Inclusion + Guaranteed-Inclusion Fallback - Context

**Gathered:** 2026-05-29
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix **STOP-THE-LINE-05**, surfaced during the Phase 21 / Plan 21-07 real-capital
LADYS retry (2nd live attempt, 2026-05-29 on the funded prod wallet): a **valid**
buy could not land via Flashbots at calm gas (4 attempts → 13-gwei priority-fee
ceiling-hit at a 0.25-gwei base fee; read-only `staticCall` returns ~242.38M LADYS
even at the bot's 5% slippage → pure **non-inclusion**, not a reverting swap;
capital safe — wallet ETH balance byte-identical, `LADYS balanceOf = 0`, no
`trades` row, 21.1 nonce-safe retry correct).

Phase 21.2 made the **sell/exit** leg resilient to exactly this (independent
priority-fee ceiling + a guaranteed nonce-locked public-mempool fallback) but left
the **buy** leg Flashbots-only with no fallback — it landed in the prior attempt
only by first-attempt luck. This phase makes a valid buy **land reliably**, with a
**buy-leg-appropriate** strategy that — unlike the sell — does **not** sacrifice
the front-run/sandwich protection that is the whole reason a fresh-launch snipe
uses Flashbots.

**The buy-leg insight (why this is NOT a copy-paste of 21.2):** a stranded *exit*
is capital loss, so the sell wants to go public FAST. A snipe *buy* is the
opposite — going public exposes it to the front-running the snipe was avoiding.
So the buy-leg fix is **hardened PRIVATE inclusion first** (the actual likely root
cause is builder coverage, not bid price — fixable privately), with a public path
reserved for **explicitly deliberate** buys that have no MEV to protect.

**Scope anchor:**
- **In scope:** (1) harden private buy inclusion (multi-builder fanout + multi-block
  targeting + higher within-affordability private ceiling); (2) a separate,
  **explicitly-invoked** deliberate/capture buy path that may go public
  (private-first → public fallback); (3) capital-safety guards (no-double-buy,
  extended entry-affordability gate); (4) per-builder inclusion telemetry +
  fail-clean-on-exhaustion + D-ALERTS. **Narrowly unblocks the 21-07 capture**
  (which only needs a deliberate established-token buy to land reliably) **and**
  hardens real snipe-buy inclusion.
- **NOT in scope:** an automatic public fallback for genuine snipe buys (forfeits
  MEV protection — explicitly rejected); heuristic auto-classification of
  snipe-vs-deliberate; new chains; new exit/snipe strategies; the 21-07 capture
  itself (resumes after 21.3 closes); the unproven 21.2 sell-leg live landing
  (a Phase 21 / 21-07 concern this phase unblocks — see Deferred/Downstream).

**The discriminator (carry into every test):** the failure is **non-inclusion of
a VALID tx**, not a revert. `staticCall` validity is the ground-truth signal that
separates "the relay won't include it" (this phase's problem) from "the swap would
revert" (out of scope). The canonical regression is "a `staticCall`-valid buy that
Flashbots won't include at calm gas now lands."

## Implementation Decisions

### D-QUALITY-FIRST [USER-BINDING] — governs every decision below
At every implementation/design choice in this phase (and downstream planning +
execution), pick the option that is **BETTER and SAFER and produces
HIGHER-QUALITY RESULTS, regardless of code complexity or LOC.** "Minimal surface /
least code / simplest" is NOT a virtue and must not be used as a tiebreaker.
Carried verbatim from Phase 18/19/20/21/21.1/21.2. Every decision below was made
under this lens — the owner repeatedly chose the safer/higher-assurance option.

### Buy-leg inclusion strategy (the core decision)
- **D-BUY-INCLUSION-PRIVATE-FIRST:** the buy-leg fix is **hardened PRIVATE
  inclusion**, NOT a public fallback for snipes. Genuine snipe buys **never
  auto-fall-back to the public mempool** — that would forfeit the front-run /
  sandwich protection the snipe uses Flashbots for. A **separate, explicitly
  deliberate** buy path may go public. Chosen over "all buys get a reason-aware
  public fallback" (knowingly weakens snipe protection) and over "narrowest:
  capture path only" (leaves real snipe-buy fragility unaddressed — under-delivers
  vs D-QUALITY-FIRST). Rationale grounded in research: at 0.25-gwei base fee a
  13-gwei-priority bundle is wildly profitable, so non-inclusion points to
  **builder coverage** (the block's winning builder never saw the bundle), not
  underpricing — and that is fixable **privately**, preserving protection.
- **D-PRIVATE-INCLUSION-HARDEN:** three mechanisms are **in-scope must-haves** for
  private buy inclusion: (1) **multi-builder submission** — add the `builders`
  field to `eth_sendBundle` so Flashbots fans the bundle out to other registered
  builders when BuilderNet doesn't win the block; (2) **multi-block / improved
  targeting** — target more than a single block per attempt and submit promptly
  (per-attempt single-block targeting at calm gas misses builder rotation);
  (3) **a higher within-affordability private buy ceiling** — let a calm-gas buy
  bid harder privately (the affordability clamp STILL bounds it; raise the ceiling
  INPUT only, mirroring 21.2's independent sell ceiling). **Exact tuning** (builder
  list, #blocks, ceiling gwei) is pinned by research via `flashbots_getBundleStatsV2`
  before the plan locks values. Chosen over "multi-builder only" and "lock intent,
  research picks mechanism" per D-QUALITY-FIRST thoroughness.

### Deliberate / capture buy path (public-capable)
- **D-DELIBERATE-EXPLICIT-ONLY:** a buy is allowed to use the public-capable path
  **only when explicitly invoked as deliberate/capture** — an operator flag or a
  dedicated capture/script path. **No heuristic** (token age / liquidity /
  "established") auto-classifies a buy as public-OK, because a misclassification
  would route a **real snipe** to the public mempool — the exact harm being
  designed out. Matches how the 21-07 capture is operator-invoked. (Heuristic
  auto-routing is a Deferred Idea, not this phase.)
- **D-DELIBERATE-PRIVATE-FIRST:** the deliberate buy path **tries hardened-private
  FIRST, then falls back to public** after a short budget — it reuses the same
  inclusion ladder, so it still protects a deliberate buy that happens to be
  MEV-sensitive, while **guaranteeing the buy lands** via the public-mempool path.
  Chosen over "straight to public" (simpler/guaranteed but gives up protection
  unconditionally) and "flag-controlled per-invocation" (more surface) per
  D-QUALITY-FIRST. The public leg is `swapExactETHForTokensSupportingFeeOnTransferTokens`
  (the buy analog of 21.2's fee-on-transfer-safe public sell), nonce-locked.

### Snipe terminal behavior (private exhausted)
- **D-SNIPE-FAIL-CLEAN:** a genuine snipe that exhausts hardened private inclusion
  (multi-builder + targeting + ceiling all tried, still not included at calm gas)
  **fails clean** — **zero ETH spent**, no `trades` row, capital safe — plus a
  **hard structured pino + Telegram alert** (token, attempts, per-builder stats,
  reason, remediation pointer). The **deliberate/operator path IS the manual
  escape**: if the operator judges the token worth it, they re-attempt it as a
  *deliberate* buy (knowingly accepting public exposure). Protection stays
  **absolute by default**; no new in-snipe escalation mechanism. Chosen over an
  interactive operator-escalation prompt (the launch window is gone by then) and a
  per-snipe opt-in public flag (reintroduces the snipe-goes-public risk via config).

### Capital safety — no double-buy + affordability
- **D-NO-DOUBLE-BUY:** a public buy fallback must never **double-SPEND ETH** if the
  stuck private bundle lands late (worse than a double-sell — real ETH out twice).
  Guard with **strict, fail-closed** logic that **mirrors 21.2 CR-02 /
  D-FALLBACK-NO-DOUBLE-SELL**: (1) the private bundle and the public fallback share
  **ONE per-wallet nonce** (single-nonce authority + 21.1 nonce-safe retry) so at
  most one tx with that nonce can land — the structural guarantee; (2) before any
  resubmit/public broadcast, **reconcile the REAL broadcast hash + nonce** (21.1
  `BroadcastHandle`, the actually-broadcast tx — NOT a pre-signed phantom, the
  21.2-12 CR-02 lesson) and **ABORT** the public buy if inclusion is inconclusive
  or the private buy may have landed. Fail-closed: a missed buy is recoverable; a
  double-spent ETH buy is not.
- **D-BUY-AFFORDABILITY-EXTEND:** extend the Phase 21.2 buy-time entry-affordability
  gate (`checkEntryExitAffordability`) so a **deliberate** buy also reserves its
  own **public fallback** gas (the deliberate path's worst case includes a public
  broadcast). The gate is **mode-aware**: a genuine snipe (private-only, no public
  fallback) is NOT required to reserve public-buy gas it will never use. Builds on
  21.2's `computePublicExitReserveWei` posture.

### Evidence strategy
- **D-EVIDENCE-BUY-INCLUSION:** because the 21-07 capture buy uses the
  **deliberate (public)** path, it will **not** exercise the snipe
  private-hardening (multi-builder). So that fix earns confidence via:
  (1) **unit + mainnet-fork proof** of the multi-builder/targeting/ceiling wiring
  (mock relay asserts the bundle is submitted to N builders with correct targeting
  and the raised ceiling input); (2) **per-builder inclusion telemetry** —
  structured logging of `flashbots_getBundleStatsV2` (which builder included,
  per-attempt simulation/seen status, target blocks); (3) **opportunistic live
  validation** on the **next real snipe** (the telemetry confirms multi-builder
  inclusion in production) — NOT a gated real-capital capture (a fresh-launch snipe
  can't be staged deterministically, and multi-builder is a well-understood
  low-risk API change). The **21-07 retry** still provides the live bar for the
  **deliberate-buy public path** AND finally unblocks the **sell-leg** live proof.
  Chosen over a gated live snipe capture (new capital/risk, non-deterministic) and
  fork/unit-only (skips production inclusion telemetry) per D-EVIDENCE-BAR spirit.

<specifics>
## Specific Ideas

- **Builder coverage, not price, is the most likely root cause** — at a 0.25-gwei
  base fee a 13-gwei-priority bundle is wildly profitable, so the bundle "not
  included" almost certainly means the block's winning builder never received it.
  That makes **multi-builder fanout** (still private, no front-run exposure) the
  highest-leverage, protection-preserving fix — which is why the buy leg is
  hardened-private-first, not public-fallback-first like the sell.
- **The buy inverts the sell's urgency logic** — 21.2's reason-aware trigger sent
  anti-rug exits public FAST because a stranded exit = capital loss. For a snipe
  buy the danger is the opposite (public = front-run exposure), so the policy
  inverts: snipes stay private, and "going public" is an explicit, deliberate,
  no-MEV-value act.
- **A double-buy is uniquely bad** — unlike a double-sell (you sell tokens you have),
  a double-buy spends real ETH twice for the same intent. The single-nonce
  guarantee makes it structurally impossible, and the reconcile-before-resubmit is
  fail-closed: when in doubt, do NOT broadcast the public buy.
- **"Never enter a position you can't exit" extends to "account for the buy's own
  guaranteed-inclusion cost"** — the deliberate path's affordability reserve now
  includes its public fallback gas; the snipe path, having no public fallback, is
  not burdened with a reserve it would never use.
- **The 21-07 capture only needs the buy as a means to obtain a position** (the buy
  records a `mev_bundle` placeholder, not an artifact) — all capture evidence is
  the SELL leg. So the deliberate-buy path is the narrow, correct unblock; it does
  not need (and should not get) the snipe's MEV protection.

</specifics>

<deferred>
## Deferred Ideas

- **Heuristic snipe-vs-deliberate classification** — auto-detecting non-fresh-launch
  / established tokens (age, liquidity depth) to route eligible buys public without
  an explicit flag. Considered in the deliberate-buy-gating decision and **rejected
  for 21.3** (D-DELIBERATE-EXPLICIT-ONLY): a misclassification routes a real snipe
  public — the exact harm. Candidate for a future phase if a safe, high-confidence
  classifier is designed.
- **In-snipe operator-escalation prompt** — a one-click operator-approved public
  retry when a snipe exhausts private inclusion. Considered in the snipe-terminal
  decision and **not folded** (D-SNIPE-FAIL-CLEAN): the launch window is gone by
  then, and the deliberate path already serves as the manual escape.
- **Gated live snipe-inclusion capture** — a dedicated operator-gated real
  fresh-launch snipe to prove multi-builder inclusion live. **Not folded**
  (D-EVIDENCE-BUY-INCLUSION): a fresh launch can't be staged deterministically and
  multi-builder is low-risk; opportunistic live telemetry covers it.

### Downstream (not 21.3 scope, unblocked by it)
- **Does the 21.2 sell leg actually land live at calm gas?** — STOP-THE-LINE-05 open
  question #2: still unproven, because the buy failed before any position/exit
  existed. This is a **Phase 21 / 21-07** concern that *this* phase unblocks (once
  the buy lands, the 21-07 retry finally exercises the sell). NOT a 21.3 deliverable.
