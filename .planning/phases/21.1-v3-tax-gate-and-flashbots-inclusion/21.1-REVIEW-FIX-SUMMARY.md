# Phase 21.1 Review-Fix: CR-01 (Critical) + WR-01 (Warning) Gap-Closure Summary

**The load-bearing 5-gwei priority-fee ceiling and the sell-gas affordability reserve — both bypassed on the buy path by a post-clamp `max(a.priorityFeeWei, chainPriority)` in all three MEV strategies (CR-01, which directly falsified D-FEE-ESCALATION) — are now enforced as the final authority on the actually-submitted fee, proven by observable regression tests on the real submitted tx fields for all three strategies even when the market rate is 10x the ceiling; and the surviving single-chain `hasHighTransferTax` real-buy footgun (WR-01: a signer-connected `swapExactETHForTokens(0n, …, {value})` with no `.staticCall` and broken NaN tax math) is deleted with its import and dead tests.**

## What was fixed

### CR-01 (Critical) — the fee ceiling + sell-gas reserve were bypassed on the buy path

**Root cause (confirmed):** `computeAffordablePriorityFee` correctly clamped the per-attempt fee to `min(MEV_MAX_PRIORITY_FEE_GWEI ceiling, affordabilityBound)`, but all three strategies then OVERRODE the clamped `a.priorityFeeWei` with the unclamped live market rate via `max(a.priorityFeeWei, chainPriority)` (flashbots/passthrough EIP-1559) / `max(chainGasPrice, baseFee + a.priorityFeeWei)` (bloXroute legacy). On mainnet the market rate routinely exceeds the 5-gwei default ceiling, so the buy submitted at the market rate — consuming the gas reserved for the exit and stranding the sell. 21.1-04's own key-decision #3 documented this override as intentional ("don't under-bid the going rate"); the bug was applying the floor AFTER the clamp instead of BEFORE it.

**Fix (clamp-is-final; direction locked by D-FEE-ESCALATION + the prompt):**
- `reconciliation.ts`: added `feeInputs.chainPriorityWei` (the strategy supplies the multiplier-scaled market rate). The helper now computes `desiredPriorityFeeWei = max(step×(attempt+1), chainPriorityWei)` and clamps THAT via `computeAffordablePriorityFee` to `min(ceiling, affordabilityBound)`. `ceilingHit` now reads the CLAMPED submitted fee (`>= ceiling` OR `>= affordabilityBound`) so fail-clean fires when no higher affordable bid is possible. Preserved semantics: attempt-0-unaffordable → `mev.escalation.unaffordable` alert + throw; not-landed + ceiling-hit → `mev.escalation.ceiling-hit` alert + throw (fail clean — never bid above the affordable cap to chase inclusion).
- `flashbots.ts` / `passthrough.ts`: `maxPriorityFeePerGas = a.priorityFeeWei` DIRECTLY (no second max()); `maxFeePerGas = baseFeeWei + a.priorityFeeWei` (no max() vs unclamped chainMaxFee — also closes **WR-03**'s modeled-vs-cap gap, since the cap now equals the effective price the reserve models). `priority <= maxFee` holds by construction.
- `bloxroute.ts` (legacy gasPrice) + `passthrough.ts` legacy fallback: same clamp-is-final treatment — the competitive floor is `scaledGasPrice - baseFee` (clamped `>= 0`) folded in pre-clamp; submitted `gasPrice = baseFee + a.priorityFeeWei`.

**NEW regression coverage (the test blind-spot that let CR-01 ship, WR-02-adjacent)** — `test/unit/mevStrategies/inclusionReconciliation.test.ts`, new describe `CR-01 — affordability/ceiling clamp is the final authority on the submitted fee` (4 tests):
- 3 per-strategy tests drive the strategy END-TO-END with a mocked market rate 10x the ceiling and assert the REAL submitted tx field (`sendBundle` arg / `wallet.sendTransaction` arg / `wallet.signTransaction` arg) — submitted priority `<= min(ceiling, bound)` (exactly the 5-gwei ceiling here), and `maxFeePerGas = baseFee + clamped priority`. These assert observables, NOT a helper reimplementation.
- 1 fail-clean test: market rate above the affordable cap + tx never lands → `mev.escalation.ceiling-hit` alert + throw, AND every submitted attempt's fee `<= ceiling` (the folded-in 50-gwei rate NEVER reached the wire — no overspend to chase inclusion).
- Updated `gasMultiplier.test.ts` Tests 7/9/10 (+ added 9b) which asserted the pre-fix bypass; they now prove the multiplier elevates the bid toward — but never past — the ceiling, with `maxFeePerGas` consistent.

### WR-01 (Warning) — dead-but-imported real-buy footgun twin

**Confirmed (zero live callers — see evidence below).** `hasHighTransferTax` (`src/utils/tokenSafety.ts:216`) was the single-chain twin of the already-deleted `hasHighTransferTaxForChain`, and the more dangerous of the two: a `Wallet`-signer-connected router calling `swapExactETHForTokens(0n, …, {value: inputAmount})` WITHOUT `.staticCall` (the comment "static by default in ethers v6" is FALSE — it SENDS a real `amountOutMin=0` buy), then misreading the `TransactionResponse` as `bigint[]` so `taxPercent=NaN` and the gate never fired.

**Fix (D-DELETE-LEGACY / D-ROLLBACK):** deleted the function from `tokenSafety.ts` (tombstone comment retained), removed the import from `src/bot.ts:12`, and deleted the 2 dead unit tests in `test/unit/tokenSafety.test.ts` that exercised it directly.
