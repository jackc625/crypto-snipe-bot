### Anomaly Diagnosis (required per project memory — not dismissed)

**Unit suite: transient `SQLITE_IOERR_TRUNCATE` in `db.test.ts` on first full run**

- **What:** The first `npm run test:unit` run failed with 1 failed suite (`db.test.ts`, `SQLITE_IOERR_TRUNCATE`) and 60 passed. The error was `Database.pragma('journal_mode = WAL')` throwing a disk I/O error during SQLite initialization.
- **Diagnosis:** This is a transient Windows parallel-execution I/O contention. Running 61 test files simultaneously causes two workers to open the same SQLite database file at nearly the same time on the Windows NTFS filesystem. The second `npm run test:unit` pass immediately after was clean: 614 passed, 0 failed, 61 files. Running `db.test.ts` in isolation produces 32 passed with no error.
- **Verdict:** Pre-existing harness artifact (Windows parallel-file-lock noise), not introduced by Phase 21.1 changes. Confirmed not on the reconciliation/tax-gate surface this phase touched. The 21.1-FORK-REHEARSAL.md and the REVIEW-FIX-SUMMARY record 614/611 passing (their runs did not hit the contention). **Not a blocker.**
