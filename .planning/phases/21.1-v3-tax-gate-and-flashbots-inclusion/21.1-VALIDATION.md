## Harm-Prevention Assertions

The minimal set that proves these bug classes cannot regress (RESEARCH §Validation Architecture):

1. **False-negative-loses-position:** native confirm reports failure WHILE `getTransactionReceipt(signedTxHash).status===1` (and/or `getTransactionCount('latest')` advanced) → `sendTransaction` resolves with the real hash (does NOT throw). Asserted per-strategy (Flashbots / bloXroute / passthrough).
2. **Double-spend:** in the misreport-but-landed case, the submit primitive (`sendBundle` / `axios.post` / `wallet.sendTransaction`) is called exactly once (`toHaveBeenCalledTimes(1)`); on a genuine resubmit, the captured tx `nonce` equals the re-fetched `'latest'`, never `base+attempt`.
3. **V3-always-blocked:** a benign V3 token reaches the buy (`countTrades buy >= 1` on fork) AND a high-tax/honeypot V3 fixture still yields `verdict!=='safe'` (`countTrades buy === 0`); the removed `hasTax` field no longer gates.
4. **Mined-but-reverted false-success:** `receipt.status===0` → `sendTransaction` throws (genuine failure) and does NOT resubmit the same nonce.
5. **Stranded-exit (D-FEE-ESCALATION):** the fee ceiling clamps so `walletBalance - buyMaxCost - reservedSellGas >= 0`; if attempt-0 can't afford the reserve, `sendTransaction` fails cleanly (balance-too-low fixture) rather than submitting an unsellable buy.
