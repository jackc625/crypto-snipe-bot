Insert this block:

```typescript
// --- Startup Environment Validation ---
interface EnvVarSpec {
    name: string;
    required: boolean;
    description: string;
}

const REQUIRED_ENV_VARS: EnvVarSpec[] = [
    { name: 'PRIVATE_KEY', required: true, description: 'Wallet private key for signing transactions' },
    { name: 'ALCHEMY_URL', required: true, description: 'Alchemy RPC endpoint URL' },
    { name: 'TELEGRAM_BOT_TOKEN', required: true, description: 'Telegram bot token for alerts' },
    { name: 'TELEGRAM_CHAT_ID', required: true, description: 'Telegram chat ID for alerts' },
    { name: 'TELEGRAM_API_ID', required: true, description: 'Telegram API ID for listener' },
    { name: 'TELEGRAM_API_HASH', required: true, description: 'Telegram API hash for listener' },
    { name: 'TELEGRAM_SESSION', required: true, description: 'Telegram session string' },
    { name: 'FLASHBOTS_AUTH_KEY', required: true, description: 'Flashbots authentication signing key' },
    { name: 'TELEGRAM_ALLOWED_SENDERS', required: false, description: 'Comma-separated allowed Telegram sender IDs' },
    { name: 'TELEGRAM_ALLOWED_CHANNELS', required: false, description: 'Comma-separated allowed Telegram channel/group IDs' },
];

function validateEnvVars(): void {
    const missing: string[] = [];
    for (const spec of REQUIRED_ENV_VARS) {
        if (spec.required && !process.env[spec.name]) {
            missing.push(`  - ${spec.name}: ${spec.description}`);
        }
    }
    if (missing.length > 0) {
        console.error(`\n[STARTUP ERROR] Missing required environment variables:\n${missing.join('\n')}\n`);
        console.error('Create a .env file with these variables or set them in your environment.\n');
        process.exit(1);
    }
}

validateEnvVars();
// --- End Validation ---
```

Place `validateEnvVars()` call immediately after the function definition. It runs at module load time, BEFORE the `rpc` and `CONFIG` constants are constructed. This ensures all env vars exist before `process.env.ALCHEMY_URL!` and `process.env.PRIVATE_KEY!` are evaluated.

The existing `export const rpc = { ... }`, `export type SupportedNetwork`, and `export const CONFIG = { ... }` remain UNCHANGED after the validation block.

**Do NOT modify** the CONFIG object, the rpc object, the addresses import, or the SupportedNetwork type. Only add the validation block between `dotenv.config()` and the first export.

**Modify `src/telegramListener.ts`:**

**1. Add whitelist parsing** after the existing constants (after line 14, the `COOLDOWN_MS` line):

```typescript
// Parse whitelist from environment
const allowedSenders = new Set(
    (process.env.TELEGRAM_ALLOWED_SENDERS || '').split(',').map(s => s.trim()).filter(Boolean)
);
const allowedChannels = new Set(
    (process.env.TELEGRAM_ALLOWED_CHANNELS || '').split(',').map(s => s.trim()).filter(Boolean)
);
```

**2. Add whitelist check** as the FIRST thing inside the event handler callback (right after `async (event: NewMessageEvent) => {`, before `const messageText = event.message.message;`):

```typescript
// --- Sender/Channel Whitelist (FIX-09) ---
const senderId = event.message.senderId?.toString();
const chatId = event.chatId?.toString();

const senderAllowed = allowedSenders.size === 0 || (senderId !== undefined && allowedSenders.has(senderId));
const channelAllowed = allowedChannels.size === 0 || (chatId !== undefined && allowedChannels.has(chatId));

if (!senderAllowed && !channelAllowed) {
    console.debug(`[TELEGRAM] Rejected message from sender=${senderId} chat=${chatId}: ${event.message.message?.substring(0, 50) || ''}...`);
    return;
}
// --- End Whitelist ---
```

**Important design choice:** When `allowedSenders` is empty (env var not set), treat as "allow all senders" to maintain backward compatibility. Same for `allowedChannels`. A message is allowed if EITHER its sender is in the senders whitelist OR its chat is in the channels whitelist. When BOTH lists are empty, all messages pass (backward compatible). When either list has entries, at least one must match.

This follows the user decision: "Both user IDs and channel/group IDs are whitelisted -- messages from non-whitelisted sources are rejected" and "Non-whitelisted messages: log sender ID and message snippet at debug level, then drop."

**3. Keep all existing code after the whitelist check** unchanged: `const messageText`, the `matches` extraction, the duplicate/throttle logic, and the `handleAlphaDrop` call all remain exactly as-is.

**4. Do NOT use `NewMessage({ fromUsers: [...], chats: [...] })`** for filtering. Per research findings, the built-in filtering silently drops messages without logging. The user decision requires debug-level logging of rejected messages, so manual filtering inside the handler is necessary. Keep `new NewMessage({})` as-is.

**Key technical note:** GramJS `event.message.senderId` is a `BigInteger` from the `big-integer` library (not native bigint). `.toString()` is the correct way to convert for string comparison against the env var values.
