<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Exit engine → pino log sink | Structured log fields cross into operator-readable telemetry; logs must NOT be treated as proof of an on-chain event |
| Flashbots strategy → relay | The bundle response (bundleHash, mined hash) originates from the Flashbots relay; logging it is read-only observation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-01-01 | Repudiation / masked failure | exit.* op logs presented as "exit happened" | mitigate | D-OP-DB-TRUTH enforced in code comments + test design: the op log is filtering-only; ground truth is `trades.amount_out` non-null + the on-chain receipt. opEnrichment tests assert op presence, NOT exit success; the receipt.decoded log explicitly does not gate on success |
| T-21-01-02 | Tampering | Op-enrichment altering exit control flow / poll timing | mitigate | Additive logging only; acceptance criteria assert clearInterval logic, return values, and the pollIntervalMs interval argument are byte-identical; tsc clean ×1 |
| T-21-01-03 | Information Disclosure | Logging the full Flashbots bundle response could leak the signed raw tx / auth identity | mitigate | Log ONLY `bundleHash` + `minedTxHash` + `block` (public, on-chain-resolvable values); never log `signedTransaction` or `FLASHBOTS_AUTH_KEY` |
| T-21-01-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages — all logging uses existing pino (`^10.3.1`) and the already-wired @flashbots/ethers-provider-bundle (`1.0.0`); RESEARCH Package Legitimacy Audit confirms zero new installs |
</threat_model>
