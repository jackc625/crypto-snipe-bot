## Info

### IN-01: Pre-commit install snippet relies on an in-tree symlink-style indirection rather than copying the script

**File:** `scripts/check-empty-files.sh:11-12`

**Issue:** The documented install command writes a tiny wrapper hook that
`exec`s the in-repo script at commit time:
```bash
printf '#!/usr/bin/env bash\nexec "$(git rev-parse --show-toplevel)/scripts/check-empty-files.sh"\n' \
  > .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit
```
This is a deliberate design choice (the script comment is upfront about
`.git/hooks/` being per-clone), and it's the right call for a project without
a hook framework — it means script edits flow to all developers via `git pull`
instead of requiring re-install. Worth noting only because a one-time-copy
install (e.g., `cp scripts/check-empty-files.sh .git/hooks/pre-commit`) would
silently go stale, so the chosen approach is the safer one. No action
required.

## Notes (not findings)

For completeness, here are concerns I considered and resolved as non-issues:

- **Shell injection via crafted file paths.** Not exploitable. `$f` is always
  quoted (`"$f"`) and lives on the LHS of `[[ ... =~ ... ]]` (literal side,
  not regex side). `git diff --cached --name-only` output never crosses
  `eval` / `sh -c`. Verified with a path containing `[name]` — handled
  correctly.

- **Filenames containing newlines.** Theoretical only — `mapfile -t` splits
  on `\n`, so a file whose name contains an embedded newline would be split
  into two array elements and likely produce a "skipping non-existent file"
  pass. Git for Windows refuses to stage such names anyway, and POSIX
  filesystems that allow them are exotic. Not a defect to flag for a
  pre-commit hook protecting a normal source tree.

- **`set -eu` interaction with empty arrays.** Verified with bash 5.2.37
  (Git for Windows): `mapfile` on empty input followed by `${#staged[@]}`
  exits 0 cleanly. The script's empty-staging-area test (Test 7) passed.

- **Allow-list bypass via `attack/fake.gitkeep`.** Not bypassable. The regex
  `(^|/)(\.gitkeep|\.keep|\.gitignore)$` requires `.gitkeep` to be the entire
  basename, so `fake.gitkeep` is correctly blocked.

- **Hook portability (Git Bash on Windows + Linux/macOS).** `wc -c` is
  POSIX, `mapfile` requires bash 4+ (universally available on macOS via
  brew, Linux, and Git Bash on Windows ships bash 5+), `git diff
  --diff-filter=AM` is portable. The shebang `#!/usr/bin/env bash` is
  correct.

- **Exit code semantics.** Confirmed: `exit 1` on detected empties, `exit 0`
  otherwise, `set -e` propagates any unexpected failure as non-zero. Will
  block the commit as required.

- **`.env.example` and `docs/GETTING-STARTED.md` coherence after `auth.ts`
  removal.** Both files are clean. `.env.example:47` instructs manual
  generation; `docs/GETTING-STARTED.md:113-117` documents the history of
  the placeholder removal explicitly.
