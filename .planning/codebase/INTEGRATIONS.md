# External Integrations

**Analysis Date:** 2026-03-19

## APIs & External Services

**Blockchain RPC:**
- Alchemy - Primary RPC provider for Ethereum Sepolia testnet
  - SDK/Client: ethers.js JsonRpcProvider
  - Auth: `ALCHEMY_URL` environment variable
  - Usage: All blockchain reads/queries via `src/config.ts` RPC configuration
  - Fallback: BSC endpoint hardcoded at `https://bsc-dataseed.binance.org/` (not currently used)

**Token Safety Checking:**
- honeypot.is API - Honeypot detection
  - Endpoint: `https://api.honeypot.is/v1/TokenInfo/`
  - Usage: `src/utils/tokenSafety.ts:checkHoneypot()` - Detects if token is a scam/honeypot
  - Fallback: On-chain static call simulation if API fails

**Liquidity Lock Verification:**
- Unicrypt Network API - Liquidity lock checking
  - Endpoint: `https://api.unicrypt.network/api/v2/locker/pair/`
  - Usage: `src/utils/tokenSafety.ts:isLiquidityLocked()` - Verifies LP tokens are locked
  - Fallback: On-chain burn check if API fails (checks if 90%+ LP tokens burned to dead address)
  - ChainId: Sepolia (11155111)

**MEV Protection:**
- Flashbots Relay - Private transaction bundling
  - Endpoint: `https://relay.flashbots.net`
  - SDK/Client: @flashbots/ethers-provider-bundle
  - Auth: `FLASHBOTS_AUTH_KEY` environment variable (signer wallet)
  - Usage: `src/utils/flashbots.ts` - Creates FlashbotsBundleProvider for MEV protection
  - Primary flow: `src/utils/txManager.ts:sendTxWithRetry()` uses Flashbots for buy transactions
  - Network: "sepolia" for testing (hardcoded in `src/utils/flashbots.ts`)

**Notifications:**
- Telegram Bot API - Alert messaging
  - Endpoint: `https://api.telegram.org/bot{token}/sendMessage`
  - SDK/Client: axios HTTP client
  - Auth: `TELEGRAM_BOT_TOKEN` environment variable
  - Usage: `src/utils/notifier.ts:sendTelegramAlert()` - Sends formatted alerts to chat
  - Parse mode: Markdown for formatted messages
  - Required env vars: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`

**Telegram Client (Message Listener):**
- Telegram MTProto API - Direct Telegram protocol access
  - SDK/Client: telegram library (v2.26.22)
  - Auth: `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION` (user session)
  - Usage: `src/telegramListener.ts` - Listens for contract address mentions in Telegram channels
  - Purpose: Detects alpha drops and triggers bot via `handleAlphaDrop()`
  - Session: Generated by `src/scripts/genAuthWallet.ts`

## Data Storage

**Databases:**
- None - In-memory only
- Local file storage via `src/utils/storage.ts` for tracking sniped tokens

**File Storage:**
- Local filesystem - JSON file-based storage
  - Tracked tokens stored in memory with `Set` structures
  - No persistent database; state lost on restart

**Caching:**
- In-memory Sets (`src/utils/blocklist.ts`, `src/telegramListener.ts`)
  - `BLOCKLIST.tokens` - Known bad token addresses
  - `BLOCKLIST.pairs` - Known bad LP pair addresses
  - `processedContracts` - Deduplication cache for Telegram messages
  - No external cache service

## Authentication & Identity

**Auth Provider:**
- None - Custom EOA (Externally Owned Account) based
  - Implementation: Direct private key signing via ethers.js Wallet
  - Private key: `PRIVATE_KEY` environment variable
  - Used for all transaction signing and contract interactions

**Telegram Authentication:**
- User-based session - Not bot-based
  - Session established via `TELEGRAM_SESSION` (StringSession from telegram library)
  - Session ID: Generated once and reused
  - No OAuth; uses MTProto protocol directly

## Environment Configuration

**Required env vars (Critical):**
- `PRIVATE_KEY` - Wallet private key for signing transactions
- `ALCHEMY_URL` - Sepolia RPC endpoint
- `TELEGRAM_API_ID` - Telegram app API ID (from my.telegram.org)
- `TELEGRAM_API_HASH` - Telegram app API hash
- `TELEGRAM_SESSION` - Serialized Telegram session (generated by `src/scripts/genAuthWallet.ts`)
- `TELEGRAM_BOT_TOKEN` - Bot token from @BotFather
- `TELEGRAM_CHAT_ID` - Target chat ID for alerts
- `FLASHBOTS_AUTH_KEY` - Private key for Flashbots relay authentication

**Secrets location:**
- Environment variables via `.env` file (not tracked in git per `.gitignore`)
- No secrets manager integration (AWS Secrets, HashiCorp Vault, etc.)

## Webhooks & Callbacks

## Contract Interaction Patterns

**Factory Events:**
- Listens to `PairCreated` events from UniswapV2Factory
  - Factory address: `CONFIG.factoryAddress` (from `src/addresses.json`)
  - Triggers: `handleNewPair()` in `src/bot.ts`

**Router Interaction:**
- UniswapV2Router02 for swaps
  - Address: `CONFIG.routerAddress`
  - Functions used:
    - `swapExactETHForTokens()` - Buy tokens
    - `swapExactTokensForETH()` - Sell tokens (normal + fee-on-transfer variant)
    - `getAmountsOut()` - Price quotes

**Liquidity Pool Interaction:**
- UniswapV2 Pair contracts for reserve queries
  - Methods: `getReserves()`, `token0()`, `token1()`
  - Usage: Liquidity verification and pricing

**ERC20 Token Methods:**
- `approve()` - Spending allowance for router
- `balanceOf()` - Token balance checks
- `allowance()` - Verify existing approval
- `symbol()`, `name()`, `decimals()` - Metadata validation
- `maxWalletAmount()`, `maxTxAmount()` - Anti-bot limit detection
