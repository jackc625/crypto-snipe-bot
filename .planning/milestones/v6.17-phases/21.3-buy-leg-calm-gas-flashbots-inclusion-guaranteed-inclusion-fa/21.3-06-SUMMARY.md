# Phase 21.3 Plan 06: Gap Closure — CR-01 + HI-01 + WR-01/02/03 + IN-01/02/03 Summary

Closed the deep-code-review findings in `21.3-REVIEW.md` (operator chose fix-within-phase, RED-proven).
The review confirmed **two capital-safety defects on the deliberate-buy path the green suite +
verifier structurally missed** — both masked because every prior deliberate test used
`amountIn === snipeAmount`, so the gate's `snipeAmount`-vs-`amountInWei` substitution was invisible.
CR-01 + HI-01 sit on the EXACT path the 21-07 real-capital retry runs (a deliberate buy, typically
larger than the snipe amount), so they had to close before the phase closes / the retry resumes.
Also closed three warnings (WR-01/02/03) and three info cleanups (IN-01/02/03). Every behavioral fix
is RED-proven against pre-fix code; the snipe path is byte-for-byte unchanged; full unit (755/755) +
integration (216/216) suites green; `tsc --noEmit` clean for both projects.

## What Was Built

### Task 1 — CR-01 + HI-01: price the REAL deliberate amount + pre-broadcast public re-check (commit `dc09e98`)
- **CR-01** (`src/preflight.ts`): `checkEntryExitAffordability(chain, mode, buyValueWei?)` now accepts the
  REAL buy value, defaulting to `ethers.parseEther(chain.snipeAmount)`. The `snipeValue` floor term is
  driven off `buyValueWei ?? parseEther(chain.snipeAmount)`. `enforceEntryExitAffordability(ctx, token,
  mode, buyValueWei?)` (`src/bot.ts`) threads it; `executeDeliberateBuy` passes the operator's
  `amountInWei`. The two snipe call sites (V2 + V3) pass **nothing** → `buyValueWei` undefined → the snipe
  floor is byte-for-byte the pre-21.3-06 value.
- **HI-01** (`src/bot.ts`, after the no-double-buy guard clears, before the public swap): a pre-broadcast
  LIVE affordability re-check re-invokes the SAME single-source gate (`checkEntryExitAffordability(chain,
  'deliberate', amountInWei)` — which internally reuses `computeWorstCasePublicExitGas`, **no new
  reserve formula**) against the live balance + fee. Fail-closed on refusal: `return null` +
  `op:'buy.fallback.affordability.refused'` pino + Telegram. This catches a base-fee rise / gas
  escalation between the entry gate and the broadcast — the only path that actually broadcasts fresh ETH.

### Task 2 — WR-01: capture the reconcile hash before the raw multi-builder fanout (commit `585502a`)
- **WR-01** (`src/utils/mevStrategies/flashbots.ts`): reordered the submit closure so the library
  `sendBundle` (block+1) — the deterministic reconcile-hash source (`bundle.bundleTransactions[0].hash`) —
  runs BEFORE the raw `eth_sendBundle` multi-builder fanout, and writes the `BroadcastHandle`
  (`signedTxHash` + `submittedNonce`) immediately. A mid-fanout relay error (e.g. a transient 5xx on
  block+2) now throws AFTER the reconcile hash is already recorded, so the no-double-buy / reconcile
  machinery can still probe a bundle that landed at block+1 (no LADYS-class false-negative / unmonitored
  position). Sign-once (`signBundle` once per attempt — Pitfall 2), the identical multi-block bytes, the
  CR-01 clamp (no second `Math.max`), `bundle.wait()` + `getBundleStatsV2` telemetry semantics all preserved.

### Task 3 — WR-02 + WR-03 + IN-01/02/03 (commit `12c88a1`)
- **WR-02** (`src/bot.ts`): snapshot `balanceOf(targetToken)` at the top of `executeDeliberateBuy`
  (before any submit); the chain-truth check now aborts on `tokensReceived = heldBalanceNow -
  heldBalanceBefore !== 0n || nonceConsumed`. An already-held token (prior partial position / airdrop /
  dust) no longer permanently blocks the public fallback when the nonce proves the private buy did not
  land; still fail-closed on any tokens received by THIS buy or a consumed nonce. Snapshot read failure →
  assumed-0 baseline (conservative). Kept the `op:'buy.fallback.aborted.chain-truth'` alert.
- **WR-03** (`src/bot.ts`): wrapped the public `getAmountsOut` in try/catch + a `length>=2` / non-null
  guard; on failure emits `op:'buy.fallback.quote-failed'` (pino + Telegram) and returns null
  (fail-closed) instead of the prior uncaught bigint TypeError in `computePublicMinOut`.
- **IN-01**: dropped the dead `_mode` param from `submitBuyTx` + its two snipe call sites (it implied a
  behavioral switch that did not exist). `BuyMode` retained (the type of the gate's load-bearing `mode`).
- **IN-02**: removed the dead `publicBuyAllowed` sentinel + its unreachable `if (!publicBuyAllowed)` guard.
- **IN-03**: added an explicit caveat log that the private `minOut=0` fallback applies ONLY to the
  un-sandwichable private leg; the public leg recomputes minOut and fails closed (WR-03).
