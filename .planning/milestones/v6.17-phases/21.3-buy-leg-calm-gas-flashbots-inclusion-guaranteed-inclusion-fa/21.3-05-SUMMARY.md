# Phase 21.3 Plan 05: Arm Monitoring on Every Landed Deliberate Buy (STOP-THE-LINE-06) Summary

Closed STOP-THE-LINE-06 — a CONFIRMED capital-safety gap: `executeDeliberateBuy` recorded a
landed buy via `recordDeliberateBuy` but NEVER armed the exit monitor or registered anti-rug
protection, leaving a held deliberate position UNMONITORED (no stop-loss/trailing/take-profit) and
RUG-UNPROTECTED at buy time, and silently dropped from the anti-rug restart-resume (no `lp_baseline`
row → excluded by `getResumeAntiRugTrades`' INNER JOIN). The fix extracts the snipe handler's
battle-tested register→monitor block into ONE shared `armPositionMonitoring` helper, refactors the V2
snipe handler to call it (behavior-preserving), and arms it from `executeDeliberateBuy`'s three landed
branches via `recordAndArmDeliberateBuy`.

## What Was Built

### Task 1 — shared `armPositionMonitoring` helper + V2 snipe refactor (behavior-preserving)
- Added module-level `armPositionMonitoring(ctx, dex, tokenAddress, pairAddress, tradeId, originalTokenAmount, buyAmountNative)` to `src/bot.ts`, extracted VERBATIM from `handleNewPairForChain`'s inline register→monitor block (former :908-947): `startExitMonitor(ctx, dex, token, feeTier=null, buyAmountNative, tradeId, originalTokenAmount)` FIRST, then `snapshotLpBaseline` + (CR-03 **awaited**) `registerAntiRugPosition` under the `op:'antirug.baseline-snapshot-failed'` try/catch. `feeTier` is `null` (V2).
- Refactored the V2 snipe handler to call the shared helper inside the `if (tradeRow)` branch; the `else 'Could not find trade ID for exit monitor'` branch preserved. The inline trio no longer appears in `handleNewPairForChain`.
- V3 handler left inline (deliberate path is V2-only).

### Task 2 — arm monitoring on every landed deliberate buy (RED-proven)
- Added `recordAndArmDeliberateBuy(ctx, token, dex, amountInWei, txHash)`: (1) `recordDeliberateBuy`; (2) post-buy `balanceOf` → `originalTokenAmount`; (3) resolve `tradeId` via `getTradeIdForPendingToken`; (4) resolve the V2 pair via `FACTORY_ABI getPair(weth, token)`; (5) `armPositionMonitoring(...)` with `buyAmountNative = ethers.formatEther(amountInWei)`, or the snipe's `'Could not find trade ID'` log if the tradeId did not resolve.
- Routed all THREE landed branches (private-landed, late-land-included, public-fallback) through `recordAndArmDeliberateBuy`. The no-broadcast branches (affordability-refused / inconclusive fail-closed / chain-truth abort) arm NOTHING.
- A `getPair` RPC failure resolves the pair to `''` so the exit monitor still arms (`snapshotLpBaseline` then fails inside the helper's try/catch → `op:'antirug.baseline-snapshot-failed'` + register skipped). A pair-resolve failure never costs the exit monitor of a held position (T-21.3-05-05).
