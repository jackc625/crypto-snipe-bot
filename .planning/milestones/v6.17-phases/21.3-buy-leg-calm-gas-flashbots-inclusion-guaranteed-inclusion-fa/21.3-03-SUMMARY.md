### Auto-fixed / clarifying additions (Rule 2 — correctness, in-scope)

**1. [Rule 2 — Correctness] Added a 'reverted' branch to the no-double-buy fail-closed set**
- **Found during:** Task 2 (implementing the inverted guard).
- **Issue:** The sell guard folds `reverted` into the not-landed balanceOf path (a reverted sell consumed no tokens, so re-selling is safe). For the BUY this is unsafe: a mined-but-reverted private buy that the node reports transiently could, on a same-intent public resubmit, double-spend ETH. The plan's `<action>` lists `included → abort`, `landed-not-ours/inconclusive → fail-closed`, `reverted/not-landed → chain-truth`. I made `reverted` fail-closed (not chain-truth) because the buy's unrecoverable harm (double-SPEND) warrants the stricter posture (D-NO-DOUBLE-BUY "bias even harder toward do-not-broadcast"; D-QUALITY-FIRST safer option).
- **Fix:** `reverted` joins `landed-not-ours` in the fail-closed branch (`op:'buy.fallback.failsafe.inconclusive'`). `not-landed` alone falls through to the stricter chain-truth check. A dedicated test (`reverted -> FAIL-CLOSED`) asserts 0 public buys.
