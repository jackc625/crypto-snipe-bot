**Deterministic real-hash extraction — the reconcile key (KEEP verbatim, `:178-182`):**

  throw new Error(`Flashbots bundle response missing bundleTransactions[0].hash for block ${targetBlock}`);

**Auth scheme to reuse for the raw call** (the strategy already builds `authSigner` at `:70`): `new Wallet(this.authKey)`. The raw `eth_sendBundle` body is signed `address:signMessage(id(body))` (research Pattern 1, verified against the lib at `node_modules/@flashbots/ethers-provider-bundle/build/index.js:793-797`).

**CR-01 fee landmine (DO NOT regress, `:117-135`):** the submit closure uses `a.priorityFeeWei` DIRECTLY (`populatedTx.maxPriorityFeePerGas = a.priorityFeeWei; populatedTx.maxFeePerGas = baseFeeWei + a.priorityFeeWei`). Never re-introduce a second `max()` against the unclamped chain rate — that was the CR-01 bypass. Raising the buy ceiling (`reconciliation.ts`) is an INPUT-only change; this line is unchanged.

**What changes here:**
1. Add a `rawSendBundle(relayUrl, authSigner, signedTxs, targetBlock, builders)` helper (research Pattern 1).
2. Replace the single `sendBundle` with: `signBundle` ONCE → `simulate(block+1)` (KEEP, `:143-156`) → loop `rawSendBundle` over `block+1 … block+MEV_BUY_TARGET_BLOCKS` with `MEV_BUILDERS` → keep the library `bundle.wait()` on `block+1` as the native-confirm signal.
3. Add `flashbotsProvider.getBundleStatsV2(bundle.bundleHash, targetBlock)` telemetry logging (`op: 'flashbots.bundle.stats'`, research Code Examples) on the not-landed path.

**Landmines (research Pitfall 1 & 2):**
- `sendBundle`/the `opts` arg DROP `builders` → must use the raw RPC (the trap is invisible to a call-count test).
- **Sign ONCE per attempt**, reuse the SAME `signedTxs` across all N blocks — re-signing per block re-fetches the nonce and breaks the deterministic-hash reconcile (Pitfall 2).

export function computeWorstCasePublicExitGas(inputs): bigint {

}

### `src/exitEngine.ts` (REFERENCE ONLY — the SHAPE the buy mirrors, NOT modified)

**The 21.2 sell ladder is the reference pattern for the deliberate buy** (with the snipe-stays-private inversion). Two regions are load-bearing:

**1. Public fallback (`exitEngine.ts:508-564`)** — quote → (approve if needed) → fee-on-transfer-safe swap, each leg nonce-locked, reason-aware minOut, D-ALERTS. The buy inverts the path (`[WETH, token]`), sends ETH `value`, and needs NO approve.

**2. No-double-sell guard (`exitEngine.ts:902-979`) — mirror EXACTLY, inverted (ETH-out is the danger):**
```typescript
if (priv.lastSignedHash && priv.lastNonce != null) {
    const rcfg = buildReconcileConfig(process.env, ctx.chain.gas.maxGasLimit, attempts, 'sell');
    const recon = await reconcileInclusion(priv.lastSignedHash, priv.lastNonce, ctx.wallet, ctx.httpProvider, rcfg.confirmWindowMs, rcfg.pollMs);
    if (recon.outcome === 'included') { /* ABORT public fallback — private landed late */ }
    else if (recon.outcome === 'landed-not-ours') { /* FAIL SAFE — do NOT broadcast (inconclusive) */ }
    // 'reverted'/'not-landed' → fall through to the balanceOf-truth guard, then public
}
// (2b) balanceOf-truth defense-in-depth: if held === 0n → ABORT (already done)
```

**Buy guard differences (research §Q7, the highest-stakes inversion):**
- A double-BUY spends real ETH twice (UNrecoverable) — bias even harder toward "do not broadcast when in doubt."
- `included` / `landed-not-ours` / inconclusive ALL abort (fail-closed).
- Defense-in-depth chain-is-truth for the buy: before the public buy ALSO verify `balanceOf(token) == 0` (no tokens already received) AND the nonce was NOT consumed (`getTransactionCount('latest') == submittedNonce`). The sell only checks balance; the buy checks both.
- Reconcile the REAL `BroadcastHandle.signedTxHash` (populated even on a throw — `flashbots.ts:224-226`, `passthrough.ts:163-164`), NEVER a pre-signed phantom (the CR-02 lesson).

## Shared Patterns

### Multi-builder submission (`MEV_BUILDERS`) — the only NEW mechanic
**Source:** research Pattern 1 (raw `eth_sendBundle`) + lib auth at `node_modules/@flashbots/ethers-provider-bundle/build/index.js:793-797`.
**Apply to:** ALL Flashbots buys (snipe AND deliberate-private leg) — it is private builder-to-builder routing, NOT public exposure (research Pitfall 3).
**Default `MEV_BUILDERS`** (verified registry, 2026-05-29): `flashbots, f1b.io, rsync, beaverbuild.org, builder0x69, Titan, EigenPhi, Gambit Labs, payload, Loki, JetBuilder, tbuilder, bobthebuilder, BTCS, bloXroute, Blockbeelder, Quasar, Eureka, Bombora` (casing matters: `Titan`, `beaverbuild.org`, lowercase `flashbots`). Conservative fallback subset if unknown-name handling proves strict (OQ1): `beaverbuild.org, Titan, rsync, builder0x69, flashbots, f1b.io, bloXroute`.

### Nonce authority (single per-wallet nonce — the no-double-buy structural guarantee)
**Source:** `withNonceLock` (`nonceAuthority.ts`) via `submitBuyTx` (`bot.ts:244-249`) and `executePublicFallbackSell` (`exitEngine.ts:543,552`).
**Apply to:** every buy submit — the private bundle AND the public fallback acquire the SAME per-wallet nonce chain, so at most one tx with a given nonce lands. `NonceManager` is banned (caches nonces). This is the structural half of D-NO-DOUBLE-BUY (the reconcile is the procedural half).

### BroadcastHandle (the real-broadcast-hash reconcile key)
**Source:** `types.ts:14-17` (`BroadcastHandle`), written by both strategies even on a throw (`flashbots.ts:224-226`, `passthrough.ts:163-164`), consumed by the sell guard (`exitEngine.ts:903-907`).
**Apply to:** the no-double-buy guard — reconcile `broadcast.signedTxHash` + `broadcast.submittedNonce`, NEVER a locally pre-signed tx (the CR-02 lesson — a re-built tx has a different keccak256 and probes a phantom hash forever).

### D-ALERTS (dotted `op` pino + Telegram)
**Source:** `enforceEntryExitAffordability` (`bot.ts:282-295`: `op: 'entry.exit-affordability.refused'`), `executePublicFallbackSell` (`exitEngine.ts:525-538`: `op: 'exit.fallback.public.submit'`), the no-double-sell guard alerts (`exitEngine.ts:910-935`).
**Apply to:** every ceiling-hit / builder-miss / fallback / fail-clean / inconclusive-reconcile. The per-builder telemetry uses `op: 'flashbots.bundle.stats'` with `consideredByBuilders` / `sealedByBuilders` from `getBundleStatsV2`.

### Affordability reserve (single source of truth)
**Source:** `computePublicExitReserveWei` (`reconciliation.ts:263-269`) and `computeWorstCasePublicExitGas` (`preflight.ts:266-277`) — identical base-fee × buffer math, no priority term.
**Apply to:** the mode-aware buy gate — add a public-BUY term (`approvalGasLimit: 0n`) only in deliberate mode; reuse the helper, do not re-derive.

### REAL-PATH test discipline (the 21.2-12 CR-02 lesson — binding per D-TEST-BOTH)
**Source:** `test/unit/exitEngine/noDoubleSellReconcile.test.ts:1-26` (documents the lesson verbatim) — mock ONLY external boundaries (DB at `:42-56`, logger at `:58-62`), exercise the REAL `escalatePrivate* → sendTxWithRetry → strategy → submitWithReconciliation` chain, assert HASH EQUALITY between the reconciled hash and the strategy's actually-broadcast hash.
**Apply to:** `test/unit/bot/noDoubleBuyReconcile.test.ts` (REAL-PATH hash-equality) and `flashbotsMultiBuilder.test.ts` (assert the raw RPC wire body's `builders` array — NOT a call-count). Config-var tests extend `inclusionReconciliationConfig.test.ts` (the env-var-controls-behavior idiom).
