## STOP-THE-LINE Escalations (capital-safety watch) — READ FIRST

**None. No NEW bug was surfaced by the full suite or the fork rehearsal (D-STOP-THE-LINE: nothing to escalate, nothing deferred).** Two pre-flagged items were assessed to root cause, not dismissed:

1. **`antirug.http-polling.error` ×43 (HTTP 400) in the fork run — DIAGNOSED, benign.** It is the anti-rug LP-rug **monitoring** poller calling `eth_getLogs` over an unbounded block range against a rate-limited archive RPC; it self-heals ("retry next tick"), is on the **position-monitoring** path (NOT the buy/sell submission path the reconciliation/tax-gate fixes touched), and did not mask anything — every lifecycle observable fired and all 4 fork tests passed (exit 0, zero `FAIL`). This is the same benign noise 21.1-03 already recorded. Out of scope (a fork-harness artifact; a real fix would bound the anti-rug backfill range). NOT a gate blocker, NOT a STOP-THE-LINE finding.
2. **Carry-forward thrown-submit/double-spend boundary (flagged by 21.1-04/05) — ASSESSED, COVERED.** Verified directly that `submitWithReconciliation` has no try/catch around its `submit` closure (a thrown submit would bypass helper-level reconciliation). The strategies handle this correctly: transport/wait TIMEOUTS are caught inside each `submit` closure and returned as `nativeConfirmed:false` (so the helper reconciles by receipt/nonce → real hash if landed), and only a genuine revert (simulated, never broadcast) or an explicit relay rejection (never broadcast) throws — in both throwing cases the tx did NOT land, so there is no double-spend risk. A thrown-but-landed path therefore cannot cause a double-spend. Exercised by the unit misreport-but-landed / mined-but-reverted / genuine-resubmit tests + the integration simulated-revert-never-broadcasts / relay-rejection-propagates / `[42,42,42]` tests. The residual *design* note (the helper itself does not reconcile a thrown closure — it relies on the strategies never throwing on a landed tx) is documented in the rehearsal doc, confirmed safe, and flagged for any future helper-level enhancement — not silently dropped.
