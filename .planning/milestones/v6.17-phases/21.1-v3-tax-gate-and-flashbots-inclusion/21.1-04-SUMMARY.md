# Phase 21.1 Plan 04: Wire All 3 MEV Strategies Through the Shared Reconciliation Helper Summary

**The critical STOP-THE-LINE-02 fix wired end-to-end: flashbots, bloXroute, and passthrough are now thin wrappers over `submitWithReconciliation` — the fetch-once+increment nonce loop and the premature `wait()===0`-only / relay-accept / `tx.wait`-timeout failure paths are gone; a buy/sell that actually lands can never again be reported failed (the LADYS harm), the retry can never double-spend, and a reverting tx is never escalated-and-resubmitted — proven per strategy with the misreport-but-landed / mined-but-reverted / nonce-safe / SC4 sell-leg tests GREEN.**

- **`FlashbotsMevStrategy.sendTransaction`** rewritten as a thin wrapper: `FlashbotsBundleProvider.create` stays outside the loop; the per-attempt `submit` closure populates `nonce: a.nonce` (helper-supplied re-fetched 'latest'), the EIP-1559 fee branch, simulates via `flashbotsProvider.signBundle`+`simulate` (eth_callBundle) before `sendBundle`, then returns `{signedTxHash: bundle.bundleTransactions[0].hash, submittedNonce: bundle.bundleTransactions[0].nonce, nativeConfirmed: (waitResponse===0)}`. `wait()===1` (BlockPassed) and `wait()===2` (AccountNonceTooHigh) both map to `nativeConfirmed:false` so the helper reconciles. ## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fee composition could emit `maxPriorityFeePerGas > maxFeePerGas` (invalid EIP-1559 tx)**
- **Found during:** Task 1 (gasMultiplier Test 7/8 went red after the rewire).
- **Issue:** My first cut set `maxFeePerGas = applyGasMultiplier(chainMaxFee)` and `maxPriorityFeePerGas = max(chainPriority, a.priorityFeeWei)`. The helper's escalated `a.priorityFeeWei` starts at a 1-gwei floor; on a tiny-fee chain (or any chain where the escalation floor exceeds the scaled cap) the priority bid could EXCEED `maxFeePerGas` — an invalid tx.
- **Fix:** Compute `priorityBid = max(multiplier-scaled chain priority, a.priorityFeeWei)`, then `maxFeePerGas = max(multiplier-scaled chain cap, baseFee + priorityBid)` so the cap always covers the bid. Applied to flashbots + passthrough.
- **Files modified:** `src/utils/mevStrategies/flashbots.ts`, `src/utils/mevStrategies/passthrough.ts`.
- **Verification:** gasMultiplier Test 7/8 assert `maxPriorityFeePerGas <= maxFeePerGas` and the multiplier-scaled values; GREEN.
- **Committed in:** `768cea9` (Task 1).
