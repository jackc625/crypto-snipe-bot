## STOP-THE-LINE Escalations (capital-safety watch) — READ FIRST

**Sibling audit result: `simulateSwapForChain` is CLEAN. No new STOP-THE-LINE finding. Nothing deferred.**

Per the MANDATORY sibling-audit clause (D-V2-TAX-REMOVE / D-STOP-THE-LINE), I audited the sibling V2-bank functions — especially `simulateSwapForChain` (`bot.ts:302`, the `canSwap` member) — for the SAME missing-`.staticCall` real-on-chain-submit pattern that made `hasHighTransferTaxForChain` dangerous.

- **`simulateSwapForChain` (`src/utils/tokenSafety.ts:397-421`): CLEAN.** Evidence: the contract is built with **`ctx.httpProvider`** (a read-only provider, `:402`), NOT `ctx.wallet`, and the swap is invoked as **`router.swapExactETHForTokens.staticCall(amountOutMin, path, ...)`** at `:409` — a read-only `eth_call` simulation that broadcasts **NO** transaction. This is the exact mirror of the safe pattern. `canSwap` is therefore kept wired in the V2 bank.
- **Contrast (the removed function):** `hasHighTransferTaxForChain` built a SIGNER-connected router (`new Contract(dexRouter, ROUTER_ABI, ctx.wallet)`, former `:495`) and called `swapExactETHForTokens(0n, …, {value: snipeAmount})` with **NO `.staticCall`** (former `:497`) — a REAL on-chain buy at `amountOutMin=0` on every V2 snipe, then misread the returned `TransactionResponse` as a `bigint[]` so `taxPercent=NaN` → `> 0.25` is `false` (silent false-negative on top of the unwanted real buy). That is the hazard; it is now gone.
- **No fix-in-flight, no file-and-defer:** the audit came back clean, so there was nothing to escalate. Had it found a real submit, it would have been raised here as STOP-THE-LINE-04 (not fixed). The grep gate also re-confirms `swapExactETHForTokens.staticCall` is still present in `tokenSafety.ts` after the edits.

## Decisions Made
- **PLAN/CONTEXT amended scope supersedes the older PATTERNS.md note.** `21.1-PATTERNS.md §220-234` (written for the original V3-only scope) said to KEEP the `hasHighTransferTaxForChain` import + function "still used by V2". - **Storage-seed over buy-then-sell for `dumpV3Pool`** (D-QUALITY-FIRST): a whale that buys its bag from the same pool and sells it back nets the price to ~neutral (a symmetric pair, minus fees) and can NEVER produce the >30% NET drop the stop-loss needs. Higher-quality/correct mechanism, chosen over a fewer-LOC buy-then-sell that would not trigger the exit.
- **`blockedReason` neutralized to `""` (not removed).** The V2 fixtures express the unblocked state by omitting the key, but the schema table documents `blockedReason` as an optional field; keeping it present-but-empty preserves the schema while satisfying the plan's literal `blocked:false` requirement.
