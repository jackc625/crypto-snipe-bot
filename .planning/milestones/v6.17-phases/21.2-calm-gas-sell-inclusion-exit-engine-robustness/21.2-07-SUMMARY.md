## Accomplishments
- **The capital-safety crown jewel (Finding D / D-FAILED-EXIT-KEEP-MONITORING).** `executeFullSell`'s success path AND catch now make the teardown decision from a RE-FETCHED on-chain `balanceOf` — the only signal that did not lie in the LADYS harm. `<= dust` → genuine close → full teardown. `> dust` → still held → `keepMonitoringFailedHeld`: persist `exit_failed_held` + `exit_failure_count++` (DB v7), KEEP anti-rug registered (NO `unsubscribeAntiRug`), do NOT `deleteExitState`, and re-arm the routine poll timer if it was cleared.

## Decisions Made
- **Dust threshold (RESEARCH A6):** relative `original_token_amount × bps / 10000` MAX a 1000-wei absolute floor. A missing `exit_state` row → relative term 0 → only the floor applies (fail-safe toward still-held — never tear down a held position on missing metadata).
- **Catch re-fetch failure → fail-safe held.** If the `balanceOf` re-fetch itself throws (RPC down mid-failure), use a `-1n` sentinel (definitely `> dust`) → keep monitoring. Tearing down on an unconfirmed balance is exactly the harm class this plan exists to prevent.
- **Routine-pause placement.** Enforced at the very top of `executeFullSell` (before the sell-lock) so a paused routine trigger does not even contend; anti-rug bypasses the check unconditionally.

## Test 6 Inversion Rationale

The pre-21.2-07 `antiRugReason.test.ts` Test 6 asserted that `executeFullSell`'s error path calls `unregisterAntiRugPosition('eth', 44)` + `deleteExitState(44)` "per D-TERMINATION". **That assertion ENCODED THE CAPITAL-SAFETY BUG** — it green-lit stripping rug protection from a still-held position (the LADYS evidence: 252,930,777 LADYS confirmed held AFTER the reported failure). A green suite was actively protecting the harm: fixing the source alone would have turned the suite red, inviting a "fix" that reverts the source to match the test.

The inverted Test 6 asserts the CORRECT behavior via OBSERVABLE EFFECTS on a failed exit of a still-held position (`balanceOf` 252.9M >> dust): `unregisterAntiRugPosition` NOT called, `deleteExitState` NOT called, `markExitFailedHeld(44)` called (persist `exit_failed_held`), and `registerExitMonitor` called (the poll timer re-armed because the anti-rug path cleared it before the sell). This is a DELIBERATE correction of a Phase-19 D-TERMINATION misapplication: D-TERMINATION always meant "tear down when the position CLOSES" — `balanceOf` is the source of truth for "closed", not the submit report. Tests 4/5 (genuine close, `balanceOf <= dust`, DOES tear down) and Test 7 (partial sell leaves the position open) are preserved unchanged in intent.
