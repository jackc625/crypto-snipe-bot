# Phase 21.2 Plan 01: Per-wallet Nonce Authority Summary

**`withNonceLock(walletAddress, op)` — a per-wallet async promise-chain mutex that serializes every same-wallet signing op (eliminating the nonce-collision/double-spend class bot-wide) while keeping different wallets independent, surviving a rejecting op without deadlock, and composing with 21.1's re-fetch-'latest' scheme (no ethers NonceManager).**

## Accomplishments
- Created `src/utils/nonceAuthority.ts` exporting `withNonceLock<T>(walletAddress, op)` — a per-wallet promise-chain mutex that guarantees no two signing ops for one wallet run their bodies concurrently, so no two ever contend for a nonce.
- Stored a never-rejecting chain tail (`run.catch(() => {})`) so a single failed op cannot poison/deadlock the wallet's chain — the next op still runs; the caller still sees the real resolution/rejection of its own op.
- Different wallet addresses get independent chains (no cross-wallet serialization).

## Decisions Made
- **Async promise-chain mutex, not a boolean Map lock.** The existing `exitManager.ts` sell-lock is a synchronous boolean check-and-set; that cannot hold a lock across the `await`s inside a signing op. A promise-chain (`prior.catch().then(op)`) is the correct primitive for an async critical section. Copied the atomicity reasoning and lowercase keying from `exitManager.ts:14-25`.
- **Never-rejecting stored tail.** Storing `run.catch(() => {})` (not `run`) in the Map ensures a rejecting op (a) does not break the chain for the next op and (b) does not surface as an unhandled rejection. The caller still receives the real `run`, so its own success/failure is faithful (Tests 3 + 4 prove both halves).
- **Keyed lowercase.** Matches `exitManager`/`detector` keying so a wallet referenced as checksummed vs. lowercase shares one chain (Test 5).
- **No `NonceManager`.** It optimistically caches nonces — the opposite of 21.1's deliberate re-fetch-'latest'-and-stop-on-advance discipline. The op inside the lock still re-fetches per attempt; the mutex only prevents concurrency.
