# Phase 21.2 Plan 08: Buy-Time Entry Affordability Gate Summary

The snipe path now REFUSES any entry the wallet cannot guarantee an exit from — at buy time, just before each (V2 and V3) submit, it checks `balance >= snipeValue + worstCaseBuyGas + worstCasePublicSellGas + cushion`, where `worstCasePublicSellGas` prices the GUARANTEED normal-priced PUBLIC exit (base fee × `EXIT_GATE_SELL_GAS_BUFFER` + approval gas), failing CLOSED on any RPC error. The thin-wallet trap (Finding A) is now impossible to ENTER, not merely survivable.

## What Was Built

### `src/preflight.ts`

1. **`computeWorstCasePublicExitGas(inputs)` (pure, exported, bigint):**
   `worstCasePublicSellGas = (sellGasLimit + approvalGasLimit) × (baseFee × sellGasBuffer)`.
   It prices the GUARANTEED PUBLIC exit — a NORMAL-priced public-mempool sell (base fee × a modest buffer, NO high private priority fee). That is the whole point of Finding A: the always-available exit must always be affordable, so the gate prices THAT, not the optimistic private path. Pricing the private ceiling (e.g. 25 gwei) would both over-reserve AND mis-target what the guaranteed exit actually costs. All scaling uses the shared `applyGasMultiplier` helper (no float drift, banned-v5-pattern-safe) — the SAME spelling the MEV strategies and the runtime `computePublicExitReserveWei` reserve use, so the buy-time gate and the runtime clamp agree on the math.

2. **`checkEntryExitAffordability(chain)` (the gate, exported, returns `PreflightResult`):**
   Fetches the wallet balance + `getFeeData()` in parallel (one round-trip, both inside the try so a throw on EITHER fails closed), derives the wei base fee (EIP-1559: `maxFeePerGas - maxPriorityFeePerGas`; legacy: `gasPrice`), then computes the floor:
   - `worstCaseBuyGas = maxGasLimit × maxFeePerGas` (the most the buy can pay)
   - `worstCasePublicSellGas` = the helper above (normal-priced + approval)
   - `cushion = parseEther(gasBuffer)` (the per-chain fixed cushion, same idiom as `checkWalletBalance`)
   Returns `passed: balance >= floor`. **FAILS CLOSED** (`passed:false`) on any RPC error or unusable fee data (mirrors `checkWalletBalance:181-193`) — a thin/unknown balance refuses the snipe. All math is bigint (T-21.2-GATE-FLOAT). A new `'entry-exit-affordability'` member was added to the `PreflightResult.check` union.

### `src/bot.ts`

3. **`enforceEntryExitAffordability(ctx, token)` (D-ALERTS wrapper):**
   Builds the `PreflightChain` shape from the `ChainContext` (which already holds `chain` + `httpProvider` + `wallet` — no reconstruction), calls the gate, and on a REFUSE emits a structured `op:'entry.exit-affordability.refused'` pino error + a `sendCtxAlert` Telegram alert carrying a sanitized reason with a `docs/operations/going-live.md` remediation pointer (D-ALERTS), then returns `false`.

4. **Wired at BOTH buy submit sites:** the V2 path (after CP2, before `sendTxWithRetry` ~:419) and the V3 path (after V3 CP2, before the V3 `sendTxWithRetry` ~:742). On `false` the snipe is skipped (`return`).

## How It Satisfies the Plan's must_haves

| Truth | Where |
|-------|-------|

| Gate fails CLOSED on RPC error | the `catch` + null-fee-data branch; Test 3 + Test 3b |

## Tests (`test/unit/preflight/exitAffordability.test.ts`, 7/7 green)

- **Test 1 (refuse thin):** balance one wei below the floor → `passed:false` + structured payload (balance, floor, `worstCasePublicSellGas`).
- **Test 2 (pass affordable):** balance at the floor and far above → `passed:true` (no false refusal).
- **Test 3 / 3b (fail closed):** `getBalance` throws → refuse; `getFeeData` throws → refuse.
- **Test 4 (public-exit math):** `worstCasePublicSellGas = (sellGasLimit + approvalGas) × (baseFee × buffer)` exactly, and is strictly LESS than the wrong private-ceiling term.
- **Test 4b (env-tunable):** raising `EXIT_GATE_SELL_GAS_BUFFER` raises the floor → a previously-affordable balance now refuses.
- **bigint precision:** exact wei boundary (at-floor passes, one-wei-below refuses).

## Deviations from Plan

**1. [Rule 2 — missing critical functionality] Gate wired at the V3 submit site too, not just the plan's named V2 path (:419).**
- **Found during:** Task 1 (reading the bot.ts snipe path).
- **Issue:** the plan/PATTERNS reference only the V2 buy submit (`:419`). bot.ts has a SECOND buy submit on the V3 path (`:742`) with the identical thin-wallet-trap exposure. Gating only V2 would leave an unexitable-entry hole on every V3 snipe — defeating the must_have "the bot can never enter a position it cannot guarantee an exit from" (T-21.2-THINTRAP is path-agnostic).
- **Fix:** factored the gate into one shared `enforceEntryExitAffordability(ctx, token)` and called it at BOTH sites (no duplicated formula). Aligns with D-QUALITY-FIRST (close the whole trap, not the named instance).
- **Files modified:** `src/bot.ts`.
- **Commit:** `075b489`.

No env vars were added: `EXIT_GATE_SELL_GAS_BUFFER` (default 2.0) and `RPC_TIMEOUT_MS` were already registered in `config.ts` + `.env.example` by 21.2-04 / earlier 21.2 waves, so D-ENV-EXAMPLE is already satisfied.
