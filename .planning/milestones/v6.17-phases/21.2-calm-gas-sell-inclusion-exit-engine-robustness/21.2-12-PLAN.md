<objective>
Fix the TWO CONFIRMED CRITICAL capital-safety regressions the Phase 21.2 deep code review (21.2-REVIEW.md) found — both regressions of invariants this phase was chartered to protect, both masked in CI by tests that mock/stub the exact mechanism that breaks. Operator approved fix-within-phase (highest-quality scope).

**CR-01 — re-entrant withNonceLock deadlock (capital-safety, HIGH):** the serial `ExitWorker` drain wraps the whole submit in `withNonceLock(wallet)` (exitEngine.ts:1254), then `executeFullSell` (the worker's `realSellExecutor`, exitEngine.ts:1149) re-acquires the SAME wallet's lock for its approval (exitEngine.ts:826/829) and public-fallback (exitEngine.ts:529/538). `withNonceLock` (nonceAuthority.ts:60-75) is a NON-reentrant promise-chain mutex → the inner acquire waits for the outer to settle, the outer waits for the inner → PERMANENT DEADLOCK on every worker-driven routine exit. The watchdog frees the drain loop but the orphaned `executeFullSell` never reaches `finally { releaseSellLock }` (exitEngine.ts:1083) → the per-token sell-lock is held forever → the DIRECT anti-rug emergency exit for that token (exitTrigger.ts → tryAcquireSellLock) is ALSO permanently blocked. Hidden in CI because the worker test uses a fake executor (`_setSellExecutorForTesting`) and the inclusion-ladder test mocks `withNonceLock` to a non-serializing passthrough.

**CR-02 — no-double-sell guard reconciles a phantom hash (capital-safety, HIGH):** `escalatePrivateSell` (txManager.ts:159-164) derives `lastSignedHash`/`lastNonce` by locally pre-signing a tx it builds itself (no MEV fee escalation, no chainId/type), but the real broadcast happens inside `sendTxWithRetry → strategy.sendTransaction` which RE-BUILDS + RE-SIGNS + broadcasts a DIFFERENT tx (clamped/escalated fees). So `reconcileInclusion(priv.lastSignedHash, …)` (exitEngine.ts:871-887) probes a hash that NEVER hit the chain → its receipt is always null → step 2a never aborts the public fallback. The sole surviving guard is the single `balanceOf` snapshot (2b, exitEngine.ts:893), which is racy against a private bundle that lands AFTER the snapshot → real double-sell window. Defeats Finding A's no-double-sell guard.

Governing constraints (USER-BINDING): **D-QUALITY-FIRST** — pick the better/safer/higher-quality option regardless of LOC. **D-STOP-THE-LINE** — surface any further new bug (do not fix-in-flight beyond this plan's scope / file-and-defer). **THE CARDINAL LESSON:** both bugs were invisible because the tests MOCKED the mechanism under test. Every fix here MUST ship a regression test that exercises the REAL path (real withNonceLock, real executeFullSell wiring, real hash equality) and that would FAIL against the current buggy code.
</objective>
