# Phase 21.2 Plan 05: Calm-Gas Sell Inclusion + Exit-Engine Robustness (Finding C decoupling) Summary

**A single serial ExitWorker drains a priority queue (anti-rug first), one nonce-locked sell at a time, with a per-position lock preventing re-entrant self-sell; poll ticks now enqueue-and-return 'continue' so the 222s poll-loop starvation is structurally fixed (exit.poll.cycle overruns:false).**

## Accomplishments
- **ExitWorker singleton** (src/exitEngine.ts): a priority queue (anti-rug=0 > urgency-market-sell=1 = stop-loss=1 > trailing-stop=2; partial=3 reserved) + serial drain loop that `await`s `withNonceLock(ctx.wallet.address, () => executeFullSell(...))` strictly one sell at a time. A late anti-rug jumps ahead of an already-queued trailing stop.
- **Per-position lock** (src/utils/exitManager.ts): `tryEnqueuePosition`/`releasePositionQueue` — a SIBLING of the existing sell-lock Map, held across the entire enqueue→drain→settle lifetime so the same `{chain:token}` cannot be double-enqueued (no re-entrant self-sell); released after settle so a future genuine re-trigger can enqueue again.
- **Poll-tick conversion** (src/exitEngine.ts): the three `await executeFullSell(...)` trigger sites in `pollExitStrategy` (trailing-stop, stop-loss, urgency) now `enqueueExit({reason})` + `return 'continue'` (NOT `'exited'`). Both identical poll bodies (startExitMonitor + resumeExitMonitor) keep the interval ARMED on a trigger; `clearInterval` is now reserved for the genuine-close path (21.2-07).
- **Tests** proving every truth via observable effects: serial drain (non-overlapping start/end timestamps), priority ordering (late anti-rug dequeued before queued trailing-stop), per-position lock (double-enqueue blocked + releases after settle), nonce wrap (submit routed through `withNonceLock` keyed by wallet), enqueue-and-return, `overruns:false` under a slow worker sell, and interval-stays-armed across two cycles.

## Decisions Made
See `key-decisions` frontmatter. Key points:
- The controllable-executor seam was chosen (over deep-mocking the MEV submit chain) so the serial/priority/lock invariants are tested by observable effects (timestamps, dequeue order, call counts), not hollow assertions — D-QUALITY-FIRST.
- The per-position lock is a genuinely new SIBLING Map, not a reuse of the sell-lock, because the sell-lock's lifetime (inside `executeFullSell`) is too narrow to cover the queued window — RESEARCH §Don't-Hand-Roll said "extend exitManager," which this does (adds to the same module/keying convention) rather than inventing a parallel structure elsewhere.
- `pollExitStrategy`'s `'continue' | 'exited'` union is intentionally preserved; the `'exited'`→`clearInterval` guard is the seam 21.2-07 will drive for genuine closes. Removing it now would be misleading-dead-code churn that 21.2-07 must undo.
