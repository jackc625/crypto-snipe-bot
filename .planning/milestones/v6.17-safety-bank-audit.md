# v6.17 Safety Bank Audit (HONEY-11)

**Audited:** 2026-05-15
**Auditor:** Phase 18 plan-execute (18-04)
**Scope:** 8 parallel-bank gates in `src/utils/tokenSafety.ts` lines 335-550 — the
defense-in-depth layer that runs in parallel with the new HoneypotChecker
dispatch (Phases 18-02..18-09).

## Methodology

Per `18-CONTEXT.md` **D-AUDIT-BAR** (lines 98-104) the audit applies two
deliverables to each of the 8 gates:

1. **Code-read** to confirm the gate exercises the underlying behavior
   (NOT method-name probing) — matches Phase 17 D-04 observable-effect
   rigor.
2. **Regression test** under `test/unit/safetyBank/<gate>.test.ts` that
   would fail if the gate ever regressed to vacuous-pass. Each test
   asserts (a) the unsafe-equivalent return on edge cases (RPC throw,
   malformed response, etc.), AND (b) at least one observable effect
   (mock-call arg, log-call with discriminating `check: '<feature>'`
   tag, or RPC method invocation).

Mock infrastructure follows the existing `test/unit/tokenSafety.test.ts`
pattern (mock `ethers.Contract` constructor + module-level logger +
axios). Each test file is self-contained: no shared fixtures between
gates so a single-gate regression cannot mask another's failure.

## Stop-the-Line Determination

Per `18-CONTEXT.md` **D-STOP-THE-LINE** (lines 165-172): "If the HONEY-11
audit OR a Phase 18 regression test reveals a production bug worse than the
V2/V3 sell-sim ones (e.g., a gate that grants buys when it shouldn't), the
bug BLOCKS Phase 18 close. Treated as a first-class v6.17 requirement
upgrade (likely HONEY-13+ or a decimal phase 18.1)."

Based on this audit, **ONE bug was found**: `isBlacklistedTokenForChain`
(lines 357-361) lacked a try/catch and would propagate an RPC throw out of
the gate. Severity assessment:

- **Failure mode:** an `eth_getCode` RPC error propagates up the
  Promise.all chain in `bot.ts` parallel-bank dispatch. Because
  Promise.all rejects on any single rejection, the resulting rejection
  is caught at the call-site and the buy is BLOCKED (the bot logs the
  error and proceeds to skip the snipe).
- **Worst case:** the bot SKIPS a token it would otherwise have snipped
  — false-negative on a safe token. The bot does NOT make a bad buy
  because the gate's failure cascades to the caller's catch path.
- **Comparison to V2/V3 sell-sim bugs:** the V2 sell-sim
  (`simulateSellForChain`, `balance=0` hard-block) and V3 sell-sim
  (`simulateSellV3ForChain`, vacuous-pass at lines 603-606) both
  failed-open: V2 incorrectly blocked every snipe (~$0 lost, opportunity
  cost only), V3 incorrectly granted every buy (real-money loss
  possible). The blacklist gate's pre-fix behavior is failing-CLOSED at
  the call-site level — it never granted a bad buy. It is therefore
  **strictly LESS severe** than either V2 or V3 sell-sim.

**Determination:** D-STOP-THE-LINE escalation **NOT triggered**. HONEY-13+
**NOT created**. Phase 18 close proceeds as planned. The gate-level fix-in-flight
(commit `6e2676d`) brings the gate into uniform fail-closed-in-isolation
compliance with the other 7 gates and locks the behavior in via the new
regression test — closing the audit-bar deliverable in the same wave.

## What Was NOT Audited

Per `18-CONTEXT.md` **D-AUDIT-BAR** the audit boundary is the 8 chain-aware
dispatch functions in `src/utils/tokenSafety.ts` ONLY. The following layers
are **explicitly out-of-scope** for HONEY-11 and DEFERRED to v6.18+:

1. **Third-party API adapter internals** under
   `src/utils/safetyProviders/`:
   - `honeypotIs.ts` (honeypot.is API)
   - `goplus.ts` (GoPlus Security API)
   - `unicrypt.ts` (Unicrypt liquidity lock API + burn-check fallback)
   - `mudra.ts` (Mudra Locker API + GoPlus fallback)

   These were spot-checked during the dispatch audit (each adapter's
   error path was confirmed to fail-closed at the boundary), but a full
   per-adapter regression suite is deferred to v6.18+ (provisionally
   tracked as v6.18 HONEY-V2-ADAPTER-AUDIT).

2. **`bot.ts` Promise.all parallel-bank dispatch** at lines 229-238. The
   audit confirms each gate's individual fail-closed posture; the
   call-site logic (combining the 8 boolean results into a buy/skip
   decision) is covered by `test/unit/tokenSafety.test.ts` and the
   future HONEY-12 selector-scan addition.

3. **HoneypotChecker dispatch** (`src/utils/honeypot/`) — net-new Phase 18
   primary path, validated under HONEY-01..10 and HONEY-12 directly, not
   HONEY-11.

## Discriminated-Union Retrofit Decision

Per `18-PATTERNS.md` **Key Cross-Cutting Decision #1** (line 1304):

> *Keep the 8 existing gates on `Promise<boolean>` for Phase 18 stability;
> layer the HONEY-11 regression tests over the boolean shape with the
> "never returns safe-equivalent on edge case" pattern. Defer
> discriminated-union retrofit to v6.18 (matches Phase 17 D-13/D-14 risk-
> aversion).*

**Decision (locked):** the 8 parallel-bank gates stay on `Promise<boolean>`
for v6.17. The HONEY-11 regression tests are layered over the boolean
shape, asserting unsafe-equivalent returns on edge cases without
requiring a return-type retrofit. Phase 18's net-new `HoneypotResult`
discriminated union (`src/utils/honeypot/types.ts`) applies ONLY to the
new dispatch layer; the parallel-bank gates retain their existing API.

**Rationale:**
- Phase 18 already touches `bot.ts:220-226` and `bot.ts:411-416` for the
  V2/V3 in-place replacements. Retrofitting all 8 gates simultaneously
  would compound the blast radius without a corresponding safety win
  (the regression tests already lock fail-closed semantics).
- Phase 17 D-13/D-14 carried forward a strict no-rip-and-replace stance
  for stable code. The 8 gates are stable (only one bug found in
  audit). v6.18+ can fold them into the discriminated-union pattern
  alongside any HONEY-V2-* extensions.
- The regression test pattern (`expect(result).toBe(true)` /
  `.toBe(false)` plus an observable-effect assertion) is sufficient to
  catch the only failure mode that matters — vacuous-pass regression —
  without changing the return type.

**Deferred (v6.18+ candidate):** unify all 8 gates on a single
`SafetyGateResult` discriminated union with explicit `verdict` and
`evidence` fields. Tracked provisionally as v6.18 HONEY-V2-UNION-RETROFIT.
