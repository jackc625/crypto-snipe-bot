## Notes

- **EXIT-LIVE-07 schema version is 7, not 6.** The 21-08 plan text said `user_version = 6`; that
  reflects the pre-21.2 schema. Phase 21.2-03 added the v7 migration (`exit_failure_count` +
  `exit_status` on `exit_state`), so a fresh-clone first boot now correctly migrates to **7**.
  The requirement is satisfied (fresh-boot migration runs + `user_version` reflects the CURRENT
  schema); the literal "6" is stale.
- **EXIT-LIVE-04 landed via the reconciliation path.** The sell bundle (targeted block 25203623)
  actually mined one block later (25203624); the native confirm reported "not included" but the
  21.1 receipt-primary reconcile (`op:mev.reconcile.included`) caught the real landing —
  preventing a false-negative that pre-21.1 could have escalated to a double-sell. The
  bundleHash→minedTxHash mapping is present and resolvable, just not via a single clean
  `flashbots.bundle.included` event.
- **Cosmetic dashboard display defect → deferred to phase 21.4 (non-blocking).** During the
  capture the dashboard rendered the held position as `Current 0.0000 / P&L -0.0010`. Debug
  session `exit-no-sell-current-zero` (resolved) root-caused this to `api/helpers/positions.ts`
  dividing a fixed pseudo-reference quote (the `queryPrice(buyAmountWei…)` foot-gun — the ETH
  cost mis-passed as a token amount → ~4053 wei) by 1e18 → ~0. Display-only: the engine's
  exit-trigger math uses the same reference as a self-cancelling RATIO, so triggers are correct.
  Not a capital-safety issue.
- **Bonus live validations earned on this single roundtrip** (the by-design operator-gated items
  that "close only on the 21-07 retry"): (1) the 21.3 BUY-leg multi-builder Flashbots fanout
  landed the buy at calm gas — STOP-THE-LINE-05 resolved live; (2) the 21.2 SELL leg landed
  privately via Flashbots at calm gas — first live proof; (3) the 21.1 reconciliation caught a
  real late inclusion — false-negative prevention proven live.

## Stop-the-Line Determination

One anomaly surfaced during the 21-07 capture: the exit engine's poll loop ran but did not fire
a prompt sell, and the dashboard showed a `Current 0.0000` valuation. It was investigated under
D-STOP-THE-LINE (debug session `exit-no-sell-current-zero`, read-only, no in-flight patch) and
**ruled out as a capital-safety issue**: the engine was correctly holding a flat token (the 0.3%
price-stop never crossed; the fork rehearsal only sold because it induced a price drop), and the
sell fired correctly via the engine's own urgency-market-sell trigger at the 30-min deadline. The
residual is the cosmetic dashboard display defect above — a non-blocking follow-up for phase
21.4, NOT a blocking escalation. **No new blocking decimal phase is required to close Phase 21.**
