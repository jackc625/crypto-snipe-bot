> Visual and interaction contract for frontend changes. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Phase Scope — UI Impact Assessment

Phase 12 is a backend-heavy gap-closure phase. The dashboard client changes are limited to:

1. **Event type rename:** `useWebSocket.ts` changes `'chain_status'` to `'chain_status_change'` (D-06, Pitfall 1).
2. **ChainControls data source:** Switch from REST-only (`useApi`) to hybrid REST + WebSocket (`useWs().chainStatuses`) so chain start/stop events push to all tabs (D-09, Pitfall 2).
3. **Stale artifact deletion:** Remove 28 `.js` files from `dashboard/src/` (D-12). Zero visual impact.

No new pages, no new components, no new visual states. All UI tokens, patterns, and components are inherited from Phase 8/10/11.

## Interaction Contract — Phase 12 Changes

### INT-03: Chain Status WebSocket Push (D-06, D-07, D-09)

**Before:** ChainControls uses `useApi('/api/chains')` for initial load. Chain start/stop only visible in the initiating tab after manual `refetch()`. Other tabs see stale data until page refresh.

**After:** ChainControls additionally consumes `useWs().chainStatuses`. When the WebSocket delivers a `'chain_status_change'` event, all connected tabs re-render automatically with the updated chain list.

| Behavior | Specification |
|----------|---------------|
| Initial load | `useApi('/api/chains')` fetches chain list via REST (unchanged) |
| Real-time update | `useWs().chainStatuses` provides WS-pushed chain data |
| Data priority | When `chainStatuses` from WS is non-empty, prefer it over stale `useApi` data |
| WS reconnect | Client refetches `/api/chains` via REST on reconnect (D-11, already implemented in `refreshFromRest`) |
| Event type string | `'chain_status_change'` on both server and client (D-06) |
| Payload shape | `{ chains: ChainStatus[] }` -- same as GET /api/chains response (D-07) |
| Re-render behavior | ChainStatusCard grid updates without page refresh (D-09) |
| Multi-tab | All authenticated tabs receive the broadcast simultaneously |

### INT-02: Corrected Price Display

**Before:** BSC PancakeSwap V3 positions may show incorrect live price (wrong quoter used).

**After:** Correct live price shown. No visual change -- same PositionTable, same `currentPrice` field, same `formatEth()` formatting. The fix is entirely in backend `positions.ts` dex resolution.

| Behavior | Specification |
|----------|---------------|
| Display format | `formatEth(pos.currentPrice)` -- unchanged |
| Stale indicator | `(stale)` suffix + warning color when `priceStale: true` -- unchanged |
| New field surfaced | `dex_name` available in API response (D-04) but not displayed in Phase 12 UI. Future phases may add a DEX badge to PositionTable. |

### INT-01: Stale Artifact Cleanup

No UI behavioral changes. 28 `.js` files deleted from `dashboard/src/`. `.gitignore` updated. The committed `.tsx` sources remain the canonical source files.
