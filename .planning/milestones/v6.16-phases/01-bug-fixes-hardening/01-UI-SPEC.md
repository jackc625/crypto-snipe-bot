## Applicability

**This phase has NO user interface.**

Phase 1 (Bug Fixes & Hardening) is a pure backend/infrastructure phase. All nine requirements (FIX-01 through FIX-09) are TypeScript/Node.js code changes: race condition fixes, Flashbots configuration, process lifecycle management, and Telegram message filtering. There are zero frontend files in the project (no .tsx, .jsx, .css, no React, no Tailwind, no shadcn).

The first phase with UI work is **Phase 8: Monitoring & Web Dashboard** (requirements DASH-01 through DASH-04, MON-01). UI-SPEC research should be performed when Phase 8 is entered.

**Evidence of non-applicability:**
- Project contains zero `.tsx` or `.jsx` files
- No `components.json`, `tailwind.config.*`, or frontend framework configuration
- Phase 1 requirements are exclusively backend: mutex for exit mechanisms, Flashbots relay configuration, nonce management, env var validation, graceful shutdown, Telegram sender whitelist
- RESEARCH.md standard stack lists only backend dependencies: ethers, @flashbots/ethers-provider-bundle, telegram (GramJS), dotenv
- No frontend work appears in the roadmap until Phase 8

## Copywriting Contract

Not applicable -- no UI in this phase.

The only user-facing text in Phase 1 is Telegram notification messages and startup error output in the terminal. These are defined in CONTEXT.md and RESEARCH.md:

| Element | Copy | Source |
|---------|------|--------|
| Sell failure alert | `*{reason} sell failed:* {error message}` | RESEARCH.md Pattern: executeSell |
| Sell success alert | `*{reason} TX confirmed*` | RESEARCH.md Pattern: executeSell |
| Sell sent alert | `*{reason} sell TX sent:* [View](https://etherscan.io/tx/{hash})` | RESEARCH.md Pattern: executeSell |
| Startup validation error | `[STARTUP ERROR] Missing required environment variables:\n  - {VAR_NAME}: {description}` | RESEARCH.md Pattern 3 |
| Rejected Telegram message | `[TELEGRAM] Rejected message from sender={id} chat={id}: {snippet}...` | RESEARCH.md Pattern 4 |
| Shutdown message | `[SHUTDOWN] Received {signal}. Cleaning up...` | RESEARCH.md Pattern 2 |

These are log/notification strings, not UI copywriting. They are documented here for completeness.
