## The 'mainnet' vs 'eth' identifier reality (critical context for Task 0)

Grep evidence (verified by orchestrator during review revision):

- `src/chainRegistry.ts:102` — ETH chain is `name: 'eth'` (lowercase, NOT 'mainnet'). Other chains: `'bsc'`, `'base'`, `'arb'`.
- `src/utils/db.ts:37` — trades schema column default: `chain TEXT NOT NULL DEFAULT 'mainnet'` ← legacy default, introduced Phase 3.
- `src/utils/db.ts:87` — trades schema v3 (recreated via CREATE TABLE trades_new) ALSO has `chain TEXT NOT NULL DEFAULT 'mainnet'`.
- `src/utils/db.ts:143-146` — `migrateJsonState()` import path HARDCODES 'mainnet' for every row: `INSERT INTO trades (token, chain, ...) VALUES (?, 'mainnet', 'buy', ...)`.
- `src/utils/db.ts:173` — `migrateJsonState()` runs unconditionally at module load; idempotent (skips if `COUNT(*) FROM trades > 0`).
- **`.bot-state.json.bak` exists at the repo root** — proves the migrator HAS run on this deployment. Any rows it imported carry `chain='mainnet'`, not `chain='eth'`.

**Consequence:** after the new `WHERE chain = ?` filter is added, calling `isTokenSniped.get(token, 'eth')` against pre-Phase-4 rows with `chain='mainnet'` will return `undefined` — the bot will silently re-snipe tokens it already sniped on ETH. Both Gemini and Codex flagged this as the dominant HIGH risk of Phase 15.

**Resolution (Resolution A1 from REVIEWS.md):** one-time forward normalization migration. A new `normalizeLegacyMainnetRows()` helper runs after `migrateJsonState()` at module load and rewrites `UPDATE trades SET chain='eth' WHERE chain='mainnet'`. Idempotent. Also updates the schema DEFAULT so future recreate paths are 'eth' from the start.

// adds `WHERE chain = ?` to isTokenSniped, a WHERE clause that binds 'eth'
// would silently miss legacy rows stamped 'mainnet' — causing the bot to
// re-snipe already-sniped ETH tokens.
//
// This helper is idempotent: once all rows are 'eth', subsequent runs
// update zero rows. Safe to call on every module load.
//
// Scope is deliberately narrow: only the exact literal 'mainnet' is
// rewritten to 'eth'. Other chain identifiers ('bsc', 'base', 'arb') are
// untouched.
export function normalizeLegacyMainnetRows(database: Database.Database = db): void {
    const result = database.prepare(
        `UPDATE trades SET chain = 'eth' WHERE chain = 'mainnet'`
    ).run();
    if (result.changes > 0) {
        logger.info(
            { rowsNormalized: result.changes },
            'Normalized legacy mainnet → eth chain identifiers in trades table'
        );
    }
}
